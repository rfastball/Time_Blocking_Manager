## 탭 역할 (확정)

| 탭 | 블록에 정하는 것 |
| --- | --- |
| 오늘 | 실행: 다음, 완료, 재배치 |
| 계획 | 시각: 날짜, 순서 안 위치, 고정 시각. 배치의 주 탭 |
| **미계획** | **모양: 길이, 쪼개기, 묶음(더미), 지난 미완료 정리** |

- 미계획에서도 날짜에 실을 수 있다. 다만 **날짜만 정하고 항상 그날 순서 끝**에 넣는 지름길이며, 계획의 날짜 머리에 놓을 때와 결과가 같아야 한다.
- 미계획에서 순서 조정이나 시각 지정이 생기면 계획 탭을 복제하는 것이므로 넣지 않는다.
- 고정 레일(시각 고정)은 계획·오늘 시간표 전용이다.

## 미계획 화면 구성 (확정)

위에서 아래로:

1. **담기 입력란**: 지금과 같다. 담은 일은 투입구 맨 위에 들어간다.
2. **지난 미완료**: 지난 날짜의 미완료 블록. 원래 날짜가 보인다. 작업대 카드와 같은 동작을 쓴다.
3. **더미 영역**: 투입구와 사용자 더미(아래 ‘더미 정책’).
4. **날짜 기둥**: 오른쪽에 둔다.
   - 오늘을 포함한 다음 근무일 5개를 블록과 같은 축척의 기둥으로 보여 준다.
   - 그날 이미 실린 양, 근무 가용 끝, 근무 외로 넘치는 분량을 표시한다.
   - 블록을 놓으면 그날 순서 끝에 들어가고, 놓기 전에 놓일 자리와 근무 외 분량을 미리 보여 준다.
5. **휴지통**: 지금과 같다.

미계획 탭의 ‘완료’ 섹션은 없앤다(‘완료 정책’ 참고).

## 블록 상태: 프로토 (확정)

- **프로토**: 담기만 하고 길이를 아직 정하지 않은 블록이다. 면 없이 테두리만 그리고, 크기 숫자를 보이지 않는다.
- 길이를 처음 조절하면(경계 끌기, ↑/↓, 도마) 길이가 확정되어 일반 블록이 된다.
- 프로토인 채로 실으면 기본 30분으로 확정한다. 막지 않는다.
- 오늘·계획의 미계획 칸에서도 프로토 표시가 보여야 한다.

## 더미 정책 (확정)

원칙: **위치는 관계로 저장하고, 좌표는 계산한다.** 사용자가 정하는 것은 ‘어느 더미의 몇 번째’이며, 픽셀 좌표는 저장하지 않는다.

**구조**
- 더미는 위쪽 레일에 카드가 순서대로 매달린 세로 묶음이다. 카드 간격은 4px이고 긴 카드도 압축하지 않는다.
- 카드 길이가 바뀌거나 잘리면 같은 더미의 아래 카드만 따라 움직인다. 다른 더미는 움직이지 않고, 겹침은 생기지 않는다.
- 더미는 왼쪽에서 오른쪽으로 놓이고, 너비가 부족하면 다음 줄로 넘어간다. 순서와 구성은 유지한다.

**투입구**
- 맨 왼쪽에 항상 있는 더미다. 옮길 수 없고, 비어도 남는다.
- 새로 담은 일과 버튼으로 미계획에 돌려보낸 일은 투입구 맨 위에 들어간다.
- 아무것도 정리하지 않으면 모든 일이 투입구에 들어온 순서대로 쌓인다. 즉 지금의 목록과 같은 상태가 된다.

**카드를 놓는 곳**
- 더미 안: 그 위치에 끼운다. 놓일 자리를 미리 보여 준다.
- 더미 손잡이 위: 그 더미의 맨 위.
- 더미 사이나 빈 곳: 그 자리에 새 더미를 만든다.
- 날짜 기둥: 그날 순서 끝.
- 끌어서 미계획으로 돌려보낸 일은 놓은 자리에 들어간다.

**더미 손잡이**
- 카드 수와 합계 시간을 보인다.
- 끌어서 더미 사이에 놓으면 더미를 옮긴다.
- 다른 더미 위에 놓으면 그 더미 아래로 합친다.
- 날짜 기둥에 놓으면 더미 전체를 순서대로 그날 순서 끝에 싣는다.
- 누르면 더미의 카드를 모두 선택한다.

**수명과 이름**
- 카드가 다 빠진 더미는 사라진다(투입구 제외).
- 날짜에 실리면 더미 소속이 없어진다. 다시 미계획으로 돌아오면 투입구에 들어간다(끌어서 놓은 경우는 놓은 자리).
- 더미에는 이름이 없다. 프로젝트·태그 범위 밖 정책을 지키기 위해서다.
- 접근성 이름은 맨 위 카드에서 따온다: `‘설계 문서 작성’ 외 1 더미, 3시간 45분`, `투입구, 3개, 1시간 15분`.

**다른 화면의 미계획 칸**
- 오늘·계획의 미계획 칸 순서는 투입구부터 더미를 왼쪽→오른쪽으로, 각 더미 안에서 위→아래로 읽은 순서다.

## 쪼개기 (확정)

**목적:** 큰 덩어리를 세부 작업으로 분해한다. 같은 일을 여러 회차로 나누는 기존 ‘나누기’도 같은 동작으로 통합한다.

**도마**
- 작업대에서 블록을 누르면 작업대 위에 2배 축척으로 크게 올라온다. 이를 ‘도마’라 부른다.
- 도마는 제목·메모 편집기를 겸한다. 작업 클릭은 제목과 메모를 우선한다는 AGENTS 원칙을 따른다.
- 도마가 열린 동안 원래 자리는 빈 윤곽으로 남고, 나머지 작업대는 흐려진다.

**조작**

| 대상 | 조작 | 결과 |
| --- | --- | --- |
| 조각 본문 | 가리키면 칼선과 양쪽 길이(15분 단위)가 보이고, 누르면 자름 | 새 조각이 생기고 그 이름 입력으로 이동 |
| 안쪽 솔기 | 끌기 | 위아래 조각이 시간을 주고받음. 합계 유지 |
| 안쪽 솔기 | 두 번 누르기 | 위아래 조각을 이음 |
| 맨 아래 경계 | 끌기 | 합계가 바뀜 |
| 프로토 조각의 아래 경계 | 끌기 | 그 조각에 길이가 생김 |
| 조각 손잡이 | 끌기 | 조각 순서 변경 |
| ‘조각 추가’ 입력 | 입력 후 Enter | 길이 미정 조각 추가. 이름만 먼저 나열할 수 있음 |
| ‘체크 항목으로 나누기’ | 누르기 | 메모의 체크 항목을 조각으로 깖. 체크된 항목은 완료된 조각이 됨 |

키보드는 조각 이름 입력에서 글줄처럼 동작한다.
- `Enter`: 지금 조각을 반으로 자름
- 빈 이름에서 `Backspace`: 위 조각과 이음
- `↑`/`↓`: 조각 사이 이동
- `Ctrl+↑`/`Ctrl+↓`: 길이 조절
- `Alt+↑`/`Alt+↓`: 조각 순서 변경

**확정 규칙**
- 닫기(‘N개로 나누기’·`Esc`)는 확정이고, ‘취소’는 이번 편집을 버린다. 기존 편집기의 ‘닫으면 저장’과 같은 규칙이다.
- 확정하면 각 조각이 독립 작업이 된다. 원래 블록이 있던 자리부터 연달아 놓인다.
  - 작업대에서 열었으면 같은 더미 안 바로 아래.
  - 날짜 블록에서 열었으면 그날 순서에 연달아.
- 조각끼리 관계는 저장하지 않는다.
- 이름을 비운 조각은 원래 제목을 쓰는 다음 회차가 된다.
- 메모는 첫 조각과, 이름을 비운 회차 조각이 받는다.
- 완료 표시된 조각은 확정 시 완료로 기록한다(‘완료 정책’ 참고). 지난 미완료를 쪼개 끝낸 부분만 완료하는 부분 완료도 이 동작으로 처리한다.
- 계획·오늘 블록 메뉴의 ‘나누기’도 같은 도마를 연다.
  - **정책 변경:** 기존에는 뒤 조각을 미계획으로 보냈지만, 앞으로는 같은 자리에 연달아 둔다.
- 블록 안 분할 경계를 상시 표시하지 않는다는 기존 규칙은 시간표에 그대로 유지한다. 솔기는 도마에서만 보인다.

## 붙이기 (확정: 넣지 않음)

- 블록 합치기를 일반 동작으로 제공하지 않는다.
- 자잘한 일을 묶어 처리하려는 필요는 더미와 ‘더미 통째로 싣기’로 해결한다.
- 잘못 자른 것은 도마 안의 솔기 잇기로 되돌린다.

## 완료 정책 (확정)

- **날짜 없는 완료를 없앤다.** 미계획에서 완료하면 오늘의 완료로 기록한다. 기록만 하고 재배치는 하지 않는다.
- 지난 미완료를 완료하면 원래 날짜에 완료로 남는다.
- 하지 않기로 한 일은 완료가 아니라 삭제(휴지통)로 처리한다.
- **이관:** 기존에 날짜 없이 완료된 기록은 접힌 보관 목록으로 남기고, 사용자가 직접 비운다.

## 전역 검색 (확정)

**배경:** 앱에는 프로젝트·태그가 없고, 더미 소속과 조각 관계도 사라진다. 그 대신 일을 찾는 수단으로 검색을 둔다.

- **위치:** 왼쪽 메뉴 줄의 ‘검색’ 버튼(`미계획` 아래, `설정` 위)과 `Ctrl+K`.
  - 미계획 탭이나 담기 입력란 옆에 두지 않는다. 검색 범위를 오해하게 만들고, 담기와 섞이면 친 글자가 새 할 일로 담기는 사고가 생긴다.
- **형태:** 화면 위쪽 가운데에 입력란과 결과 목록만 있는 패널을 띄운다. `Esc`로 닫으면 원래 포커스로 돌아간다.
- **대상:** 제목과 메모의 부분 일치. 미계획(투입구·더미), 모든 날짜(지난 날 포함), 완료, 휴지통.
- **결과:** 줄마다 제목과 현재 위치를 보인다. 예: `투입구`, `‘설계 문서 작성’ 외 1 더미`, `10월 14일 · 순서 3`, `10월 9일 · 완료`, `휴지통`.
- **이동:** 결과를 고르면 해당 탭의 그 자리로 가서 블록을 강조한다. 날짜 작업은 계획의 일 보기, 미계획은 작업대, 휴지통 항목은 휴지통을 펼친다.
- **조작:** `↑`/`↓`로 고르고 `Enter`로 이동한다. 한글을 조합하는 중에도 결과가 갱신된다.
- **넣지 않을 것:** 필터, 검색 문법, 저장된 검색, 초성 검색, 담기 입력란의 중복 제안.

## 저장해야 하는 것 (구조는 구현자가 정함)

- 블록의 프로토 여부
- 미계획 블록이 속한 더미와 더미 안 위치, 더미들의 순서
- 투입구는 항상 존재하는 기본 더미로 취급

이관은 기존 관례를 따른다. 다운그레이드 접근을 버전 검증으로 막고, 이관 직전에 ‘업데이트 전’ 백업을 남기며, 백업·복원에 새 정보를 포함한다. Rust가 모든 쓰기를 검증한다는 원칙은 그대로다.

## 지킬 원칙

- 모션은 PRODUCT.md를 따른다. 직접 조작에 지연·기울기·반동을 넣지 않고, 주변 이동과 착지만 짧게 전환한다. 동작 줄이기 설정을 존중한다.
  - 쪼개기 전용 애니메이션 연출은 이번 범위가 아니다(사용자가 취소함).
- 화면에 조작을 풀이하는 상시 안내 문구를 넣지 않는다. 기능명, 라벨, 현재 상태, 오류와 복구는 유지한다.
- 키보드만으로 모든 동작에 접근할 수 있어야 한다. 시안의 키 조합을 기준으로 하되 기존 단축키와 충돌하면 정리하고 보고한다.
- 한글 조합 중에는 Enter 명령을 실행하지 않는다.
- 네 테마 모두에서 프로토·더미 레일·솔기·근무 외 표현이 구분되어야 한다.
- 960×640 최소 창과 760px 이하 한 열 배치를 지원한다. 날짜 기둥과 도마의 좁은 화면 배치는 구현자가 정하고 보고한다.

## 구현 세부사항

비워 둔다. 코드베이스를 읽고 구현 계획(작업 단위, 저장 구조, 컴포넌트 구성, 테스트 범위)을 직접 세운다. 계획은 착수 전에 사용자에게 요약해 확인받는다.

## 진행 방식과 완료 기준

1. 착수 전에 이 문서의 결정을 PRODUCT.md와 docs/decisions.md에 정책 절로 반영한다. 기존 ‘나누기’ 규칙, 미계획 완료 목록, 미계획 입력 행 설명처럼 대체되는 문장은 함께 고친다.
2. AGENTS.md대로 작업 단위마다 검증한 뒤 로컬 커밋한다. 저장 구조 이관, 작업대, 도마, 완료 정책, 전역 검색은 서로 다른 커밋으로 나눈다.
3. 기존 테스트 정책([docs/test-policy.md](test-policy.md))에 맞춰 규칙 테스트를 추가한다. 빌드와 타입 검사를 통과해야 하고, 브라우저 미리보기에서 주요 흐름을 직접 확인한다.
   - 담기 → 투입구 → 더미 정리 → 쪼개기 → 날짜에 싣기
   - 지난 미완료 부분 완료
   - 검색으로 찾아 이동
4. 결정과 다르게 구현했거나 결정이 부족해 직접 정한 부분은 최종 보고에 따로 모아 적는다.

# Cycle 3 — 조치 프롬프트

근거: `docs/cycle3-critique-report.md`(F1–F8 및 사소한 관찰)

이 문서는 작업 패키지(WP)마다 Claude Code에 그대로 붙여 넣을 프롬프트를 담는다. 각 프롬프트는 독립 세션에서 실행되도록 썼다.

## 실행 순서

토큰을 먼저 정리하고, 그다음 "고장"으로 읽히는 버그, 그다음 시안 복원 순서로 진행한다.

| 순서 | WP | 대상 | 명령 | 사용자 결정 필요 |
|---|---|---|---|---|
| 1 | WP0 | 기반: 색·타입 토큰, 시간 표기 | `typeset` (색은 새로 넣지 않고 토큰 정리만) | 없음 |
| 2 | WP1 | 상세창 잠금 함정과 버튼 정리 (F3) | `harden` → `distill` | 없음 |
| 3 | WP2 | 내비게이션 (F4) | `clarify` + `harden` | 없음 |

모든 WP 프롬프트에 앞에 붙여 쓴다. 각 프롬프트는 "공통 지침을 따른다"로 이 절을 참조한다.

```text
[공통 지침 — BLOKKY Cycle 3]
프로젝트: C:\Users\rfast\Desktop\Projects\Time_Blocking_Manager (Tauri 2 + Vite + TypeScript, 네이티브 DOM/CSS, Rust/SQLite)

먼저 읽기:
- PRODUCT.md, DESIGN.md, docs/decisions.md, docs/test-policy.md
- docs/cycle3-critique-report.md에서 이 WP가 다루는 F 항목

  - 파일이 크므로 grep으로 필요한 부분만 읽는다. G1~G4(5~12번)는 적용하지 않는다.

지킬 원칙 (위반하면 실패):
1. 시각 기준은 확정 B/D 시안과 DESIGN.md다. 새 브랜드 스타일, 웹폰트, 외부 라이브러리를 들이지 않는다.
2. 업무 데이터는 SQLite가 기준이고 Rust가 모든 쓰기를 검증한다. UI 검증은 미리보기용일 뿐 Rust 검증을 대신하지 않는다. Rust 규칙 변경은 docs/cycle3-fix-prompts.md의 D 항목이 승인된 경우에만 한다.
3. 로드 실패나 저장 실패를 빈 목록이나 성공으로 표시하지 않는다. 초안은 항목 저장 완료와 구분한다. 복원 이전 요청 차단(epoch)과 SaveQueue 의미는 바꾸지 않는다.
4. 범위 밖 기능을 추가하지 않는다: 알림, 추천, 자동 재배치, 협업, 클라우드, 반복, 태그, 통계. D 항목은 승인된 것만 구현한다.
5. 코드 관용을 따른다.
   - src/main.ts는 밀집한 한 줄 함수 스타일이다. src/style.css는 줄 단위로 묶인 압축 형식이다. 파일 전체를 재포맷하지 않는다.
   - 줄 번호는 2026-10-08 기준이므로 함수 이름으로 찾는다.
   - 새 순수 로직은 src/의 별도 모듈로 분리해도 된다(queue.ts, settings.ts 방식).
6. 색과 크기는 DESIGN.md 토큰(:root 변수)만 쓴다. 새 토큰이 필요하면 DESIGN.md 앞부분 frontmatter와 본문, .impeccable/design.json을 함께 갱신한다.
7. 상태는 색만으로 전달하지 않는다. 선택, 완료, 지남, 작업 불가, 오류는 색과 글자 또는 형태를 함께 쓴다. 키보드 포커스 윤곽(2px, offset 3px)을 유지한다. prefers-reduced-motion을 존중한다.

impeccable:
- 이 WP에 지정된 /impeccable 명령의 reference를 따른다.
- UI 편집 직전에 craft-floor.md를 읽는다.
- 끝나면 impeccable detect를 한 번 실행한다. 정적 스캔은 템플릿 문자열을 보지 못하므로, 개발 서버 URL 스캔도 함께 한다.

산출물:
```

## WP0 — 기반: 토큰, 타입 척도, 시간 표기

```text
/impeccable typeset src/main.ts

공통 지침을 따른다. 대상은 docs/cycle3-critique-report.md §5의 "타입 척도", "색 토큰 이탈", ".selected 3중 의미"와 단위 혼용(휴리스틱 2)이다. 이후 WP들이 이 기반을 쓰므로 화면 구조는 바꾸지 않는다.

1. 색 토큰 정리 (src/style.css)
   - 하드코딩 hex 약 40종을 조사해 DESIGN.md 토큰으로 대응시킨다. 대응표를 산출 문서에 남긴다.
   - 빨강 계열 6종(#ac351d #a04121 #c84c36 #ba3825 #853b13 #922b1c)은 의미별로 최대 2개로 줄인다: error(글자·테두리), 겹침 미리보기 강조.
   - 확정 시안 1의 미완료/지남 색을 새 토큰으로 추가한다: overdue #B4451F, overdue-surface #FBF3EF, overdue-border #F0C9B8. DESIGN.md Colors 절에 의미("시간이 지났지만 완료되지 않음")를 적는다. 두 번째 브랜드색이 아니라 상태색이다.
   - 회색 바탕 변형(#f4f5f8 #f2f4f8 #eff1f5 #eff0f3 #edf0f6 등)은 canvas / control-hover / selected-surface / line 중 하나로 흡수한다.
   - 쓰지 않는 --radius 변수는 지운다.
2. 타입 척도
   - 현재 11종(10/11/12/13/14/15/16/17/18/20/23px)을 6종 이하로 줄인다. 최소 크기는 11px다(10px 금지).
   - 패널 제목(h2)은 작업 제목(14/500)과 크기나 굵기로 분명히 구분한다. 검출기 flat-type-hierarchy가 사라져야 한다.
   - 17px처럼 척도 밖의 값은 없앤다. DESIGN.md typography frontmatter와 본문을 갱신한다.
3. 상태 클래스 분리
   - .selected를 의미별로 나눈다: 달력 선택 날짜, 기간 버튼 aria-pressed, Inbox 토글 aria-expanded. ARIA 속성을 스타일 기준으로 쓴다.
   - 달력의 hover 배경과 선택 배경을 다르게 한다. 선택은 inset 2px blue + selected-surface, hover는 control-hover.
4. 시간 표기 통일
   - 순수 함수 formatDuration(분)을 src/format.ts에 둔다.
     - 60분 미만: "45분"
     - 정시: "2시간"
     - 그 외: "1시간 30분"
   - `${free(key)/60}h`, `빈 시간 ${…/60}시간`, `${t.duration}분`처럼 흩어진 표기를 모두 이 함수로 바꾼다. 6.75h 같은 소수가 사라져야 한다.
   - 날짜는 ISO(YYYY-MM-DD)를 사용자에게 보이지 않는다. 기존 dateLabel 계열로 "10월 7일 (화)" 형식을 쓴다.
     - 대상: taskRow의 지난 미완료 날짜(main.ts:148 부근)

완료 기준:
- CSS 안의 hex 값은 :root 정의에만 있다(사선 무늬의 두 회색은 토큰으로 승격하거나 예외로 문서화한다).
- 렌더된 font-size는 6종 이하이고 최소 11px다.
- 화면에 소수 시간이나 ISO 날짜가 없다.
- 시각 결과는 기존 B/D 인상과 같다. 회귀 비교 스크린샷을 1440×900에서 오늘·계획 두 장 찍는다.
```

## WP1 — 상세창: 잠금 함정 제거와 행동 정리 (F3)

```text
/impeccable harden src/main.ts  (이어서 /impeccable distill)

공통 지침을 따른다. 대상은 docs/cycle3-critique-report.md F3이고, 기준 시안은 .reference/3-source.html(항목 상세)이다. 관련 함수: openEditor, renderEditor, checklistHTML, bindChecklist, saveEditor, persistDraft, ask.

1. 잠금 함정 제거 (최우선)
   - 현재 동작:
     - #close-editor는 d.close()만 호출한다(main.ts:242).
     - dirty 초안이 남은 채로 다른 항목을 열면 errorMessage만 띄우고 막는다(main.ts:230).
   - 바꿀 동작 1 — 닫기:
     - X, Esc(cancel), 닫기 버튼에서 editorDirty이면 dialog 안 하단에 인라인 확인 바를 띄운다. window.confirm은 쓰지 않는다.
     - 문구: "저장하지 않은 변경이 있어요." 버튼: [저장하고 닫기](주요) [초안으로 남기고 닫기] [변경 버리기]
     - "초안으로 남기고 닫기"는 지금의 persistDraft 동작이다. 남긴 뒤에는 상태줄에 "‘제목’ 초안이 남아 있어요 [이어서 편집]"을 보인다.
   - 바꿀 동작 2 — 다른 항목 열기:
     - dirty 초안이 있을 때 다른 항목을 열면, 막지 말고 초안이 있는 항목의 상세창을 다시 연다.
     - 상단에 "먼저 ‘제목’의 변경을 정리해 주세요"와 [버리고 ‘새 항목’ 열기]를 보인다.
   - 깨면 안 되는 것: 초안 보존 경로(persistDraft, load_draft), SaveQueue 실패·재시도 동작.
2. 행동 정리 (7개 → 주요 1 + 보조 1 + 더보기)
   - 하단 주요: [저장] (현재 "변경 저장"). 보조: [완료로 표시] / [미완료로 되돌리기].
   - "⋯ 더보기" 버튼(aria-haspopup="menu", aria-expanded)에 [Inbox로 돌리기], [삭제]를 넣는다. 삭제는 기존 확인 절차를 유지한다.
   - "독립 할 일 추가"는 지운다. 캡처 진입점 중복이다.
   - "초안 버리기"는 dirty일 때만 보이는 보조 텍스트 버튼으로 둔다.
3. 헤더와 일정 상자 (시안 3)
   - 제목을 큰 인라인 입력으로 둔다. 별도 "항목 상세" 제목은 접근 이름(aria-labelledby)으로만 남긴다. 처음 포커스는 제목 입력에 둔다(지금은 닫기 버튼).
   - 일정 상자는 날짜·시작 시각·소요 시간을 나눠 보여 주고, 아래에 "종료 15:45 · 블록 길이와 같음"을 계산해 표시한다.
   - 상태 배지:
     - 완료 항목: "완료"
     - 시간이 지났는데 미완료: "지남"(WP0의 overdue 토큰, 글자 병기)
     - 미배치: "Inbox"
4. 체크리스트 중복 제거
   - 본문 [ ]/[x] 문법은 docs/decisions.md 결정이므로 유지한다.
   - 미러 체크박스 목록은 "체크리스트 3/5" 머리글을 가진 접힘 영역으로 바꾼다. 항목이 5개 이하면 기본으로 펼친다. 본문 라벨의 "체크 문법 [ ] / [x]" 노출은 placeholder 예시로 옮긴다.
   - 헤더에 "체크 3/5"를 요약 표시한다.
5. 오류는 한 곳에만
   - 상세창이 열려 있는 동안 편집 관련 오류는 dialog 안 #editor-recovery 한 곳에만 표시한다. 상태줄과 #editor-status에 같은 문장을 중복으로 찍지 않는다.
   - 문구는 WP5 문구표를 따른다. WP5보다 먼저 실행하면 아래 두 줄만 바꾼다:
     - "최신 목록을 불러왔습니다. 초안을 복사하거나 비교한 뒤…" → "다른 곳에서 이 항목이 바뀌었어요. 입력한 내용은 그대로 있어요." (존재하지 않는 비교 UI 약속 삭제)
     - 버튼 "최신 버전으로 다시 저장" → "내 입력으로 저장". 확인 문구 → "다른 곳에서 저장된 내용 위에 지금 입력을 저장할까요?"
6. 효율
   - Ctrl+Enter로 저장한다.
   - 모달 등장에 opacity 0→1을 추가한다. 140ms, 지금의 6px 이동은 유지하고 reduced-motion이면 끈다.
   - 높이가 창의 95%를 넘지 않게 하고 내부 편집 영역만 스크롤한다. Cycle 2 동작을 유지한다.

완료 기준 (브라우저에서 재현):
- 수정 → X → 확인 바 표시. 세 선택지가 각각 기대대로 동작한다.
- 초안을 남긴 상태에서 다른 항목을 누르면 초안 항목이 다시 열린다. 어떤 경로로도 "열리지 않는" 상태가 없다.
- 하단 가시 버튼은 3개 이하다(닫기 제외).
- 첫 포커스는 제목이다. Tab 순서는 제목 → 일정 → 본문 → 체크리스트 → 행동이다.
- 같은 오류 문장이 화면에 두 번 나오지 않는다.

테스트: "dirty 상태 + 다른 항목 열기 → 초안 항목 재개" 판정을 순수 함수로 분리할 수 있으면 Node 테스트 1건을 추가한다(test-policy brief 작성).
```

# 한 화면·몰입 실험 구현 계획 (2026-10-13)

브랜치 `exp/one-screen`(워크트리 `.claude/worktrees/one-screen`)에서 진행한 실험이다. 2026-10-13 사용자가 채택해 master에 합쳤고, 이 문서의 결정은 [decisions.md](decisions.md)의 ‘2026-10-13 한 화면과 몰입’으로 옮겼다. 아래는 진행 기록으로 남긴다.

근거: [상용 플래너 조사](commercial-planner-research-2026-10-13.md), [한 화면 시안 2판](https://claude.ai/artifact/ADfbhaDuo9neEpWeEfVyyn).

## 목표

- 탭(오늘·계획·준비·검색·설정)을 없앤다. 화면은 **작업 화면**(왼쪽 준비 도크 + 오른쪽 캘린더)과 **몰입 화면** 둘이다. 설정은 톱니에서 열고 돌아온다. 검색은 지금처럼 Ctrl K 오버레이다.
- 준비 목록과 날짜를 한 번씩만 보인다. 가공(넓은 도크)과 배분(좁은 도크)은 도크 폭으로 나눈다. 폭은 명시적 조작으로만 바뀐다.
- **제품의 핵심 동작을 잃지 않는다.** 아래 '지킬 동작'의 모든 줄은 새 자리가 있어야 하며, 없앨 때는 이 문서에 이유와 함께 적는다.

## 기준선 (착수 시점, 21b1319)

- `npm test` 66/66, `npm run build` 통과, `node scripts/ui-check.mjs` 76/76.
- 각 단계는 끝날 때 이 셋을 다시 통과해야 한다. UI 시나리오는 탭 이동만 새 조작으로 바꾸고 단언은 유지한다. 단언을 바꾸거나 지울 때는 커밋 메시지에 이유를 적는다.

## 단계

각 단계는 독립 커밋이며, 끝날 때 기준선 검사를 통과한다.

1. **셸과 도크.** 레일을 위 막대로 바꾸고, `inbox` 화면을 넓은 도크로, 계획 드로어를 좁은 도크로 옮긴다. 시작 화면은 작업 화면(주). 몰입 버튼은 지금의 오늘 화면을 연다. 메뉴의 준비 판별을 카드 출처로 바꾼다. UI 시나리오의 이동 도우미를 새 조작으로 바꾸고, 도크 세 폭과 화면 전환 시나리오를 더한다.
2. **단축키.** T(오늘), D·W·M·2(기간), `[`(도크 접기·펴기), `]`(넓게·좁게), F(몰입), `?`(목록), Esc(몰입에서 작업 화면), A(몰입 중 담기). 입력란·한글 조합·수정키·이미 처리된 키·열린 대화상자에서는 받지 않고, 키 판별은 `e.code`로 한다. 도마의 Esc(확정) 같은 지역 처리가 먼저다.
3. **몰입.** ‘다음’ 카드에 완료(→ 다음 블록으로 포커스), +15분, 나중에(선반 맨 위), 남은 블록이 없으면 배분 막대 옆에 ‘오늘 끝 · 완료 N’(준비 칸이 오른쪽 맨 위로 오는 기존 규칙 유지). 대기열·여러 선택·옆 패널 편집기·재배치·시간표·준비 칸은 유지한다. **결정(2026-10-13, 사용자):** ‘시간 경과 지연 표시 없음’ 원칙(PRODUCT.md 17행, decisions 63·100행)을 유지한다. 그래서 시계 기준의 지금 블록·남은 시간·초과는 두지 않는다. ‘다음’은 시계와 무관한 남은 첫 유동 블록이다. 연장은 15분 스냅 원칙에 맞춰 +15분만 둔다.
4. **넘침 해결.** 날짜 머리의 근무 외 표시 옆에 ‘준비로’(넘친 만큼 뒤 유동 블록을 선반 맨 위로), 오늘 머리에 예상 끝 시각.
5. **블록 옆 편집.** 팝오버로 다시 만들지 않고 같은 모달 대화상자를 블록 옆에 놓는다(2026-10-13). 닫기 확인·초안·충돌 처리를 건드리지 않기 위해서다. 주 블록에서 닫은 뒤 포커스가 블록으로 돌아오지 않는 문제는 가운데 대화상자에서도 똑같이 일어나는 기존 문제라 따로 다룬다.
6. ~~항상 위 작은 타이머 창.~~ **하지 않는다(2026-10-13, 사용자).** 상용 제품에서 이 창의 값은 남은 시간·초과를 계속 보이는 데 있는데, 3단계에서 그 표시를 두지 않기로 했다. 남는 것은 ‘다음’ 제목과 완료뿐이고, 이는 몰입 화면의 카드가 하며, 앱 밖 입력은 빠른 캡처 창이 맡는다. 늘 떠 있는 창은 시간 경과를 압박으로 읽히게 해 원칙과 어긋나기 쉽고, 창 사이 동기화·네이티브 수동 검증 비용이 크다. 다른 앱에서 완료하러 오가는 일이 잦다고 확인되면 새 창보다 전역 단축키나 트레이 메뉴를 먼저 검토한다.

1–5단계로 실험을 마친다. 채택하면 위 결정을 decisions.md로 옮기고 master에 합친다. 남은 확인: 실제 Windows 설치본과 한글 입력기, 주 블록 편집기를 닫은 뒤 포커스가 돌아오지 않는 기존 문제(master에서 따로).

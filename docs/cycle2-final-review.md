# Cycle 2 — 최종 독립 확인

2026-10-08. **판정: SHIP — 이번 세 P2 수정 범위.** 확인한 경로에서 남은 material regression은 관찰되지 않았다. 전체 제품 출시 인증이나 native 저장 검증을 뜻하지 않는다.

## 범위와 방법

`PRODUCT.md`, `DESIGN.md`, Assessment A/B, 수정 기록과 `src/main.ts`, `src/settings.ts`, `src/style.css`의 관련 구현을 읽었다. Impeccable polish/audit의 기능 완결성, 오류 복구, 포커스·ARIA, 최소 창 크기, 기존 시스템 일관성 기준을 적용했다. Windows 데스크톱 제품 범위에 맞췄으며 모바일·dark mode를 새 요구로 삼지 않았다.

별도 IAB 탭 1개에서 `http://127.0.0.1:1420/`의 예시 데이터를 사용해 960×640 및 1440×900을 **한 번의 묶음 확인**으로 검증했다. 실제 클릭·입력·드래그·스크롤과 AX, 스크린샷, 읽기 전용 DOM 측정을 사용했다. context와 detector를 재실행하지 않았다. Assessment B의 단일 detector 실행 결과 0건은 과거 증거이며 이 최종 확인의 새 검사 결과로 포장하지 않는다. 소스·테스트 변경 및 테스트 재실행 없음.

## 세 이슈별 판정과 실제 증거

| 기존 이슈 | 판정 | 이번 행동과 결과 |
|---|---|---|
| 설정 오류 위치·취소 뒤 잔존 | 해결 | 월요일 작업 불가 시간에 `09:00-09:30 출근 루틴`, 빈 줄, `잘못된 문법`을 입력하고 저장. 인라인에 `월요일 작업 불가 시간 3줄: “12:00-13:00 점심” 형식으로 입력하세요.`가 표시됐다. `document.activeElement.id=day-breaks-0`, `aria-invalid=true`, `aria-describedby=day-breaks-error-0`을 확인했다. 필드는 y≈317–377에 있고 오류와 포커스 테두리가 함께 보였다. `변경 버리기` 후 원래 값 복구, 오류 hidden, 두 ARIA 속성 제거를 확인했다. 이후 빈 줄을 포함한 유효 입력 `12:00-13:00 점심 확인`으로 저장하여 반영된 값과 `시간 설정을 저장했습니다.`를 확인했다. |
| 다른 날짜에도 오늘 순서로 표기 | 해결 | 다음 기간 클릭 시 상단 `10월 9일 금요일`, 목록 `10월 9일 금요일 순서`로 일치했다. rail의 오늘 클릭 시 `10월 8일 목요일`·`오늘 순서`·배치 3건으로 복귀했다. 설정 진입 후 날짜 이동은 AX에서 사라졌고 `.date-nav.hidden=true`였다. |
| 짧은 상세에서 저장이 화면 밖 | 해결 | 960×640에서 설계 문서 초안 작성 상세를 열었다. 항목 상세 제목·닫기, 업무 제목 입력, 변경 저장·완료·Inbox 행동 및 저장 상태가 처음부터 보였다. 메모 초기 높이 100px, 저장 영역 y≈512–591, 상태 y≈571–591이었다. 메모 오른쪽 아래 손잡이를 실제 드래그해 높이 약 177px로 늘렸고, 내부 스크롤 약 124.6px 후에도 상단 제목 y≈54–78과 저장 영역 좌표가 유지됐다. 변경 저장 클릭 후 `미리보기에 반영했습니다`, 닫기 클릭 후 오늘 화면 복귀를 확인했다. 업무 제목 입력은 스크롤 본문에 있으며 고정된 제목은 대화상자 제목이다. |

소스에서도 `parseBreaks`가 빈 줄을 건너뛰면서 원래 index+1을 사용하고, 설정 입력 오류가 저장소 오류와 별도 상태임을 확인했다. 문법 정상 제출과 버리기 경로는 `showSettingsValidation(null)`을 호출한다. 저장소 오류 보존은 소스 근거이며 native 오류를 발생시켜 검증한 것은 아니다.

## 넓은 창 및 유지된 품질

- 1440×900 오늘 화면에서 목록+시간표, 계획/Inbox 화면에서 여러 주 달력+선택 날짜 시간표+Inbox 구조와 기존 파랑·회색 B/D 시각 체계를 스크린샷으로 확인했다.
- 넓은 창 상세의 메모는 약 304.7px이며 저장 영역 y≈772–851로 화면 안에 있었다. 닫기 후 원래 항목 버튼으로 포커스 복귀가 AX에 나타났다.
- 이번 탭에서 수집된 warning/error 로그는 빈 배열이었다. 전역 런타임 무오류나 성능 측정 결과로 확대 해석하지 않는다.
- 예시 데이터·비영속성 안내가 계속 표시됐고 상세 저장 문구도 미리보기임을 분명히 했다.

## 제한과 종료

현재 확인 범위에서 추가 수정이 필요한 material regression 없음. cosmetic 탐색이나 새 리팩터링은 제안하지 않는다. 실제 Tauri/SQLite 저장, 백업·복원, 실패 큐·충돌·다중 창, 한국어 IME 조합, 전체 키보드/보조기기 발화, 대비 전수 측정, 성능 및 실제 자정 경과는 미검증이다. 전체 WCAG AA 통과 또는 완벽 점수를 주장하지 않는다.

처음 A의 **29/40은 10개 UX 휴리스틱 평가**다. 별도의 **20점 기술 audit** 척도와 직접 비교하지 않으며 이번 제한된 확인에서 새 총점을 산출하지 않는다. 기존 세 문제의 행동 증거로 개선을 판단한다.

확인 종료 후 viewport override를 reset하고 본인 탭을 닫았다. 부모가 운영하는 서버 PID 33520은 종료하지 않았다. Git diff는 이 디렉터리가 Git 저장소가 아니어서 사용할 수 없었다. 이 검토자가 만든 파일은 본 보고서뿐이며 애플리케이션 소스는 수정하지 않았다.

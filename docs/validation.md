# BLOKKY 0.1.0 검증 기록

최초 검증일: 2026-10-08. Windows x64, 로컬 WebView2, Node 24.18.1, Rust 1.99.0.
아래 기록은 시점별 확인 범위다. 최신 검증 범위는 각 항목의 날짜와 확인 내용을 기준으로 읽는다. 출시 인증이나 모든 Windows 환경의 호환성 보장은 아니다.

## 2026-10-11 오늘 대시보드 두 열과 독립 스크롤

- 시간표 띠와 실행 흐름의 두 열로 바꿨다. 오른쪽은 다음/상세 → 남은 블록 → 미계획의 DOM 순서이며 내용만큼 높이를 쓴다. 시간표의 완료 칸을 유지하고 시간 구간과 오른쪽 흐름이 창의 남은 높이에서 각각 스크롤한다. 로드·복구 화면은 높이 제한 대상에서 제외한다.
- 1440×900·960×640에서 두 열의 높이와 페이지 넘침, 빈 실행 목록, 긴 미계획 제목, 키보드 완료·상세·순서 이동 후 포커스를 확인했다. 760px에서는 한 열과 상세 대화상자를 확인했다. 기존 편집·계획 검사가 네 테마와 저장·메뉴·분할·날짜 이동을 함께 확인했다.
- 실제 포인터 검사로 스크롤한 시간표의 순서 이동, 가려진 시간 구간의 드롭 거부, 드래그 도중 스크롤 후 고정 시각 미리보기와 저장 일치, 놓을 때 고정 판정이 바뀌지 않는 것을 검증했다. 키보드로 이동한 작업은 이동 애니메이션 뒤에도 스크롤 경계 안에 포커스 여백을 남긴다.
- 명시적 UI owner **36개 확인**(editor 10 / plan 18 / today 8). 첫 묶음 34/36, 관련 재검증 5/6, 키보드 여백 수정 후 마지막 최소 창 1/1로 실패를 해결했다. Node **46/46**, TypeScript·Vite 최종 빌드 및 레이아웃 detector 통과. 소켓 기반 Edge 실행기 연결 문제로 동일 시나리오를 임시 파이프 어댑터에서 실행했다. 정규 실행기나 새 의존성은 추가하지 않았다.
- 화면 근거는 gitignored `.tools/dashboard-two-column-confirm/today-initial.png`와 `.tools/dashboard-two-column-keyboard/today-960.png`다. 브라우저 예시 데이터로 검증했으며 실제 Windows 앱·터치·사용자 SQLite 데이터는 이번에 검사하지 않았다.

## 2026-10-11 직접 조작 모션 개선

- 대시보드 감사 후속 `f47519a`의 깨끗한 작업 트리에서 시작했다. 기존 포커스·좁은 창·대비·접힌 목록 개선을 유지했다.
- 본문에서 든 블록은 잡은 지점을 포인터에 유지하고, 배치 예정 빈칸은 별도로 즉시 표시한다. 레일 고정·해제 임계값과 15분 스냅은 유지한다. 직접 크기 조절은 즉시 반영하며, 주변 블록·천장·셔터는 160ms 감속, 착지는 140ms 감속으로 전환한다. 지연 충돌·착지 반동·기울기와 관련 코드·타이머를 제거했고, 새 드래그는 이전 착지 정리 타이머를 취소한다. 짧은 든 블록도 제목과 예상 시각을 한 줄에 표시한다.
- 배포 빌드의 Edge 예시 화면에서 CDP 포인터 입력과 rAF DOM 좌표를 관찰했다. 1440×1000·960×1000에서 36px 높이 증가가 목표 ±1px 안에 안정되는 시간은 일반 모션 약 **300→33ms**였다. 동작 줄이기는 두 폭 모두 약 **33ms**로 유지했다. 단일 위·아래 입력 후 든 블록은 약 **16ms**, 빈칸은 약 **33ms**에 목표를 반영했다.
- 연속 드래그 3회에서 잡은 지점과 포인터의 세로 차이는 약 **98→0px**였다. 손을 멈춘 뒤 빈칸이 계속 움직이던 **261~276ms** 구간이 사라졌다. 관찰 프레임 간격은 약 16.7ms(최대 16.8~16.9ms)였다. 이 값은 한 환경의 예시 작업 측정이며 전체 데이터 규모나 GPU 성능 지표가 아니다.
- Node **43/43**, 최종 TypeScript/Vite build 통과. 명시적 Edge editor/today **18/18**, 계획 **16/16** 통과. 첫 묶음의 새 포인터 검사에서 센서 활성화 이동을 추종 측정으로 혼동한 한 실패를 수정했다. 6px 활성화 후 두 rAF 안에 활성 상태를 확인하고, 그 뒤 가로·세로 방향 전환을 각각 두 rAF 안에 검증한다. 마지막 한 줄 표시 보완 뒤 동일 포인터 시나리오와 일·주 화면을 좁게 재확인했다.
- 실측·화면은 `.tools/motion-audit`(이전), `.tools/motion-after`, `.tools/motion-final`; UI 결과는 `.tools/motion-ui`, `.tools/motion-ui-confirm`에 있다. 임시 스크립트·프로필·녹화·수치 파일은 커밋하지 않는다.
- Impeccable 검출기는 변경 대상에 한 번 실행했다. 수정하지 않은 레일 홈의 width 전환 경고 1건과 기존 반경·글자 크기 advisory 12건은 유지했다. 새 효과·색·글꼴을 추가하지 않았다.
- Sol은 동작 구현, Terra는 기존 UI 회귀 검사 확장, 부모는 통합 검토·프레임 계측·짧은 블록 표시 보완·문서 갱신·로컬 커밋을 담당했다. Tauri 저장 지연, 물리 터치, 스크린리더, 설치 파일 재패키징은 미검증이며 사용자 DB는 사용하지 않았다.

## 2026-10-11 대시보드 감사 후속

- 대기열 완료 후 다음 완료 버튼(마지막이면 미계획 입력), 상세 패널 닫기 후 원래 버튼, 드로어 닫기 후 토글로 포커스를 돌린다. 저장 중 다른 컨트롤로 이동한 포커스를 빼앗지 않는다. 개발 StrictMode의 재마운트에도 ‘다음’ 카드 복귀를 유지한다.
- 계획의 지난 날짜·월 밖 날짜·완료 작업에 쓰던 텍스트 투명도를 제거했다. 배경 톤·점선 경계·취소선을 유지하며 기본/G1/G3/G4의 날짜·배분·2주 작업 텍스트에 대해 합성 대비 4.5:1 이상을 UI 시나리오로 확인했다. 달력 hover 그림자는 역할 색상을 따른다.
- 960×640에서 오늘의 미계획은 시간표 끝을 기다리지 않고 대기열 바로 아래에 배치된다. 내용이 창보다 길면 스크롤하며, 입력 포커스 시 입력칸이 뷰포트 안에 들어오는 것을 확인했다. 1440px 기본 배치와 기존 계획 960/1024px 시나리오도 확인했다.
- 접힌 완료·휴지통은 펼칠 때 행을 만든다. 같은 예시 완료 1건의 닫힌 목록은 행 1→0개, 하위 요소 14→1개로 줄었다. 휴지통 이웃 탐색은 반복 검색 대신 map 인덱스를 사용한다. 실제 대량 데이터 입력 지연이나 프레임 속도 향상은 측정하지 않았다.
- Node **43/43**, 최종 TypeScript/Vite build 통과. 첫 Edge 묶음 40/42 뒤 두 실패를 해결했고, 해당 editor/today 재검증 **18/18** 및 변경 없는 plan/inbox **24/24**로 대상 42개를 검증했다. 결과·화면은 `.tools/dashboard-workflow-20261011`과 `.tools/dashboard-workflow-confirm-20261011`에 있으며 임시 산출물은 커밋하지 않는다.
- Impeccable 검출기는 변경 대상별 한 번 실행했다. 기존 반경·글자 크기 advisory 7건은 유지하고 새로운 차단 항목은 없었다. Sol이 접근성/배치, Terra가 목록 최적화를 맡았고 부모는 코드·화면 검토, 통합 검증, 변경에 맞춘 문서 갱신과 로컬 커밋을 담당했다.
- 브라우저 예시 데이터와 헤드리스 Edge의 마우스·키보드 입력을 사용했다. 실제 WebView2 저장, 물리 터치, 스크린리더, 설치 파일 재패키징은 이번 검증 범위가 아니다. 사용자 DB는 사용하지 않았다.

## 실제 Windows 앱 확인

내장 프런트엔드를 포함한 디버그 데스크톱 실행 파일에서 수행했다. 브라우저 미리보기의 가짜 저장을 근거로 삼지 않았다. 데이터는 `.tools/ui-check`에 분리했다.

- 한글 제목을 입력하고 Enter로 Inbox 저장, 메모·체크리스트 저장, 앱 재시작 후 보존.
- Inbox에서 시간표 10:00로 실제 포인터 드래그 배치, 기존 블록을 11:15로 이동.
- 하단 핸들 드래그로 30분에서45분으로 변경, 15분 눈금 적용.
- 점심시간으로 드래그하면 원래 배치를 유지하고 오류 표시.
- 상세에서 11:15 시작·60분을 저장하면 서버가 점심 충돌을 거부. 입력·본문 유지, 모달 내부 복구 버튼 접근 확인.
- 실패 요청 해제 후45분으로 수정·저장 성공. SQLite 읽기 확인: 동일 항목, 메모 유지, 11:15 시작·45분·revision6.
- Ctrl+Shift+Space로 캡처창 열기, 한글 제목 Enter 저장, 저장 확인 후 창 숨김. DB에서 미배치·30분 항목과 빈 초안 확인.
- Alt+F4로 메인창을 닫으면 창 목록에서 사라지고 프로세스는 유지됨.
- 저장 상태 하단 고정, 인접월 날짜 문맥, 모달 내부 실패 복구를 별도 화면 검토로 확인.

실제 입력 검증 중 HTML5 드래그가 WebView에서 동작하지 않는 문제를 발견해 Pointer Events로 수정했다.

## 아직 확인하지 않은 범위

- 깨끗한 Windows 또는 네트워크가 차단된 VM에서 설치·업그레이드·제거.
- 실제 한글 IME 조합 중 Enter, 다중 모니터·고배율, 960×640 최소 창의 전체 조작 흐름.
- 트레이 메뉴를 통한 종료·재열기, Windows 로그인 자동실행, 다른 앱과 전역 단축키 충돌.
- 파일 선택 대화상자를 포함한 백업 내보내기·복원 전체 UI 흐름. 저장 서비스의 백업·복원은 실제 파일 테스트로 확인했다.
- OS 강제 종료·전원 차단·디스크 가득 참·실제 권한 오류, 장기간·대량 데이터 성능.

미확인 항목을 통과로 간주하지 않는다. 사용자 실사용 데이터의 최초 입력 전에는 다른 위치로 백업 내보내기와 복원 흐름을 별도 검증하는 것이 다음 검증 단계다.

## Impeccable 감사 1회차 후 확인

같은 날짜에 서브에이전트 기술 감사·UX 검토 → 수정 한 묶음 → 확인 한 묶음을 수행했다. 상세는 [감사 보고서](impeccable-audit-cycle-1.md).

- 프런트 Node 테스트 2→3개, 모두 통과. 새 사례는 실제 CaptureDraft와 실패한 SaveQueue를 연결하여 이전 캡처 재시도의 성공이 새 입력을 지우지 않는지 검증한다.
- TypeScript/Vite 빌드 통과. Rust 저장소 로직은 변경하지 않아 기존 6개 저장 테스트를 반복하지 않았다.
- Chromium 브라우저 미리보기 960×640에서 Inbox와 시간표의 동시 노출, 가로 overflow 없음, 15분 블록 제목 확인.
- 날짜 Enter 선택 후 동일 날짜에 focus 유지, 길이 핸들 ArrowDown 후 15→30분 및 핸들 focus 유지.
- 충돌 배치를 수정하고 변경 저장을 누르면 안내와 ‘입력 유지하고 수정’에 focus. 해당 동작 후 재저장 성공.
- 브라우저 console error 0. 넓은 창에서도 기존 B/D 세 영역 구조가 유지됨.
- 완료 응답 중 새 메모 보존은 sequence 보호를 소스 재검토했다. 실제 Windows에서 저장 지연/실패를 주입한 전체 앱 회귀 시나리오는 이번에 실행하지 않았다.

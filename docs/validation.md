# BLOKKY 0.1.0 검증 기록

최초 검증일: 2026-10-08. Windows x64, 로컬 WebView2, Node 24.18.1, Rust 1.99.0.
아래 기록은 시점별 확인 범위다. 최신 검증과 산출물은 마지막 2026-10-09 앱 내부 백업 관리 항목을 기준으로 읽는다. 출시 인증이나 모든 Windows 환경의 호환성 보장은 아니다.

## 자동 검증

`./scripts/run.ps1 test`: 8개 통과.

| 계층 | 증거 | 결과 |
|---|---|---|
| Rust 실제 파일 SQLite 통합 6개 | 재시작 보존, revision 충돌, 요청 재시도 중복 방지 | 통과 |
| 동일 통합 테스트 | 겹침·불가시간·주말·자정 넘김·잘못된 간격 거부, 인접 배치 허용, 이동 시 ID 유지, 근무시간 충돌 거부 | 통과 |
| 동일 통합 테스트 | 복원 전 원본 보존, 안전 백업 실패 시 복원 중단, 이전 epoch 요청 거부, 잘못된 DB 자동 초기화 금지 | 통과 |
| 동일 통합 테스트 | 새 초안을 낡은 저장 응답이 지우지 않음, 초안 존재 시 복원 차단 | 통과 |
| 동일 통합 테스트 | 32일 시뮬레이션에서 시간별24개·날짜별30개 보존, 백업 메타데이터·무결성 확인 | 통과 |
| Node 저장 큐 2개 | 실패한 선행 쓰기 보존, 명시적 재시도 순서, 새 쓰기가 남을 때 idle 오표시 방지 | 통과 |

마지막 실행의 Rust 테스트 본체 3.56초, Node 프로세스 96.84ms. 신규 테스트 의존성은 없으며 최초 컴파일 시간은 별도다. 설계 근거는 [test-policy.md](test-policy.md).

## 실제 Windows 앱 확인

내장 프런트엔드를 포함한 디버그 데스크톱 실행 파일에서 수행했다. 브라우저 미리보기의 가짜 저장을 근거로 삼지 않았다. 데이터는 `.tools/ui-check`에 분리했다.

- 한글 제목을 입력하고 Enter로 Inbox 저장, 메모·체크리스트 저장, 앱 재시작 후 보존.
- Inbox에서 시간표 10:00로 실제 포인터 드래그 배치, 기존 블록을 11:15로 이동.
- 하단 핸들 드래그로 30분에서45분으로 변경, 15분 눈금 적용.
- 점심시간으로 드래그하면 원래 배치를 유지하고 오류 표시.
- 상세에서 11:15 시작·60분을 저장하면 서버가 점심 충돌을 거부. 입력·본문 유지, 모달 내부 복구 버튼 접근 확인.
- 실패 요청 해제 후45분으로 수정·저장 성공. SQLite 읽기 확인: 동일 항목, 메모 유지, 11:15 시작·45분·revision6.
- Ctrl+Shift+Space로 캡처창 열기, 한글 제목 Enter 저장, 저장 확인 후 창 숨김. DB에서 미배치·30분 항목과 빈 초안 확인.
- Alt+F4로 메인창을 닫으면 창 목록에서 사라지고 프로세스는 유지됨.
- 저장 상태 하단 고정, 인접월 날짜 문맥, 모달 내부 실패 복구를 별도 화면 검토로 확인.

실제 입력 검증 중 HTML5 드래그가 WebView에서 동작하지 않는 문제를 발견해 Pointer Events로 수정했다.

## 아직 확인하지 않은 범위

- 깨끗한 Windows 또는 네트워크가 차단된 VM에서 설치·업그레이드·제거.
- 실제 한글 IME 조합 중 Enter, 다중 모니터·고배율, 960×640 최소 창의 전체 조작 흐름.
- 트레이 메뉴를 통한 종료·재열기, Windows 로그인 자동실행, 다른 앱과 전역 단축키 충돌.
- 파일 선택 대화상자를 포함한 백업 내보내기·복원 전체 UI 흐름. 저장 서비스의 백업·복원은 실제 파일 테스트로 확인했다.
- OS 강제 종료·전원 차단·디스크 가득 참·실제 권한 오류, 장기간·대량 데이터 성능.

미확인 항목을 통과로 간주하지 않는다. 사용자 실사용 데이터의 최초 입력 전에는 다른 위치로 백업 내보내기와 복원 흐름을 별도 검증하는 것이 다음 검증 단계다.

## Impeccable 감사 1회차 후 확인

같은 날짜에 서브에이전트 기술 감사·UX 검토 → 수정 한 묶음 → 확인 한 묶음을 수행했다. 상세는 [감사 보고서](impeccable-audit-cycle-1.md).

- 프런트 Node 테스트 2→3개, 모두 통과. 새 사례는 실제 CaptureDraft와 실패한 SaveQueue를 연결하여 이전 캡처 재시도의 성공이 새 입력을 지우지 않는지 검증한다.
- TypeScript/Vite 빌드 통과. Rust 저장소 로직은 변경하지 않아 기존 6개 저장 테스트를 반복하지 않았다.
- Chromium 브라우저 미리보기 960×640에서 Inbox와 시간표의 동시 노출, 가로 overflow 없음, 15분 블록 제목 확인.
- 날짜 Enter 선택 후 동일 날짜에 focus 유지, 길이 핸들 ArrowDown 후 15→30분 및 핸들 focus 유지.
- 충돌 배치를 수정하고 변경 저장을 누르면 안내와 ‘입력 유지하고 수정’에 focus. 해당 동작 후 재저장 성공.
- 브라우저 console error 0. 넓은 창에서도 기존 B/D 세 영역 구조가 유지됨.
- 완료 응답 중 새 메모 보존은 sequence 보호를 소스 재검토했다. 실제 Windows에서 저장 지연/실패를 주입한 전체 앱 회귀 시나리오는 이번에 실행하지 않았다.

브라우저의 예시 저장으로 SQLite 저장·복원의 안정성을 새로 판정하지 않는다. 기존 미확인 Windows 항목도 그대로 남는다.

## 공식 명령 설명 기반 순차 피드백 2회차

공식 [기존 디자인 개선](https://impeccable.style/docs/improve-design/)의 문제 발견→집중 개선→결과 확인 흐름과 [명령 설명](https://impeccable.style/docs/)을 바탕으로 구성했다. 사용자 요청에 따라 모든 서브에이전트를 순차 실행했다.

1. `cycle2_design_review`: 독립 critique A — UX 29/40, P2 세 건.
2. `cycle2_evidence_review`: A 결과를 보지 않은 독립 B — CLI detector 1회 0건, 동일 세 문제를 실제 조작으로 확인.
3. `cycle2_focused_fix`: clarify·harden·adapt·polish를 해당 세 문제에 적용. 세션 사용량 제한으로 소스 수정 전 중단됐으며, 사용자 재개 요청 후 이 단계부터 이어갔다.
4. `cycle2_final_review`: 960×640와 1440×900 한 묶음으로 확인, 세 수정 범위 SHIP. 이후 새 전체 감사 점수는 산출하지 않았다.

결과: 설정 오류의 요일·실제 줄 위치/초점/ARIA/해제, 선택 날짜 제목과 오늘 복귀, 짧은 상세창에서 고정 제목·저장·상태가 확인됐다. 메모 resize 100→177px 및 내부 스크롤 후에도 주요 행동이 유지됐다. 브라우저 error/warn 로그 없음.

테스트 5/5, TypeScript·Vite·Rust release·NSIS 패키징 통과. 설치 파일 207.96 MiB. 소스 변경은 프런트 영역이며 Rust 저장 테스트 6개를 불필요하게 반복하지 않았다. 실제 Windows 저장 오류 주입·IME·전체 접근성은 이번에 검증하지 않았다.

평가 근거는 [A](cycle2-assessment-a.md)·[B](cycle2-assessment-b.md), 변경은 [수정 기록](cycle2-fixes.md), 판정은 [최종 검토](cycle2-final-review.md)에 있다. read-only 브라우저 API로 탐지 오버레이 주입은 불가능하여 CLI+실제 화면 검증으로 대체했다. 이번 대상의 저장된 critique는 첫 기록으로 추세 비교 대상이 없다.

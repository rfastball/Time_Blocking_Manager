- 현재 제품은 제목·메모·시작 날짜/시각·15분 단위 소요시간·완료 여부를 가진 작업을 제공한다. `src/types.ts:1`, 명령 목록은 `src/types.ts:10`. 종료는 시작+소요시간으로 계산한다(`src/main.ts:406`).

- 작업 복제·분류/캘린더 표시 숨김·검색·저장 후 실행 취소·삭제 후 복구는 데이터 모델과 명령·UI에 없다(`src/types.ts:1`, `src/types.ts:10`, `src/main.ts:411`). 삭제 안내가 “되돌릴 수 없어요”라고 명시한다(`src/main.ts:436`). 블록 나누기(`src/main.ts:355`)는 일반 복제 기능의 대체 증거가 아니다.

## 실기기 및 기준 확정이 필요한 후속 검증

1. 실제 Windows 배포 빌드를 사용자 데이터와 분리된 저장소로 실행해 생성/편집/날짜 이동/드래그·취소/단축키·한글 IME·모달 포커스의 핵심 작업을 묶음 검증한다. 특히 상세창 Ctrl+Enter 조합 경로를 재현한다.
2. 자정 유지와 절전 복귀를 오늘/계획 화면 각각에서 확인한다. 계획 화면의 오늘 표시 갱신과 선택 날짜 정책을 명시한다.
3. 지원 최소창·확대 범위·키보드/터치·스크린리더를 확정하고 실기기로 검사한다. 제목과 메모를 전부 읽고 짧은15분 블록을 선택할 수 있는지 확인한다.
4. 일반 캘린더 원문 P0 계약과 현재 시간블록 제품 계약의 차이를 결정한다. 제외 범위만으로 원문40개 필수시험의 합격을 선언할 수 없다.
5. 지원 계약에 맞춘 기준·밀집 데이터를 정의하고 대표 기기/배포 버전/표본 수/작업군/관찰 시간/허용폭을 먼저 고정한다. 표시 완료까지의 보기전환·콜드스타트·장시간 메모리를 측정한다. 저장 서비스 처리시간과 UI 표시시간을 별도 기록한다.

현재 실제 실행 실패로 확정된 프런트엔드 제품 회귀는 없다. 단, 이것은 결함 부재나 출시 P0 통과를 의미하지 않는다. UI 미실행, 미지원 목표, 성능 기준 미확정 및 IME/시간경과의 소스상 위험이 남는다.

## 2026-10-09 앱 내부 백업 관리

사용자 결정에 따라 파일 선택 대화상자 기반 가져오기·내보내기를 제거한다. 설정에서 자동 시간별/날짜별 백업과 직접 만든 백업을 한 목록으로 보여 주고, **지금 백업**은 같은 로컬 `backups` 폴더에 UUID 이름으로 생성한다. 목록은 유형·생성 시각·작업 수를 표시한다. 손상된 항목은 오류 이유와 함께 비활성화한다. 유효한 백업을 선택하면 전체·배치·완료 수를 확인한 뒤 같은 화면에서 데이터 교체를 확인하고 복원한다.

자동 시간별 24개·날짜별 30개 보존은 유지한다. 직접 만든 UUID 백업과 복원 전 안전 백업(`before-restore-<UUID>`)은 자동 정리하지 않는다. 외부 디스크 내보내기와 임의 파일 가져오기는 제품에서 제공하지 않는다. 미저장 초안 보호와 복원 전 현재 기록의 안전 사본을 유지한다.

외부 문서는 개발 판단 근거이며 런타임에는 외부 URL/API/폰트를 사용하지 않는다.

## 2026-10-09 기간 보기와 근무 모델

Google Calendar 공식 도움말의 일/주/월/사용자 지정 보기와 요일별 근무 시간 방식을 참고했다.
- https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DDesktop&hl=en
- https://support.google.com/calendar/answer/7638168?hl=en

BLOKKY에서는 4주를 월과 통합하고 주/2주/월을 제공한다. 주는 시간 격자로 충돌과 빈 시간을, 2주는 날짜별 작업 제목으로 가까운 계획을, 월은 배치량·여유시간으로 업무 분포를 판단한다. 아래 추가 확장에 따라 우측 날짜 상세는 2주·월에서 유지하고 주는 넓은 격자를 사용한다.

근무는 요일별 기본 일정에 날짜 예외를 우선 적용한다. 근무 범위 밖과 이름 있는 반복 금지시간이 배치 불가 영역이며 해당 날짜에서 바로 조정할 수 있다. 휴가는 그 날짜를 비활성화하고, 조퇴는 종료 시각을 변경한다. 이미 배치된 작업과 충돌하면 영향을 먼저 보여주고 할 일함 이동에 동의해야 변경한다. 사용자가 확인한 주 40시간·5일은 비교 목표이며 자동 근태 측정이나 법정 근무 검증이 아니다.

## 2026-10-09 할 일함과 캘린더 조작 확장

사용자가 요청한 ‘담기 → 크기 정하기 → 배치하기’를 기존 네 테마 안에서 구현한다. 독립 할 일함은 날짜 없이 캡처할 공간이고 계획의 트레이는 배치할 작업을 고르는 공간이다. 기본 주간 보기에서 중복 날짜 상세를 걷어내고 격자 너비를 확보한다. 월·2주는 날짜 상세를 유지하며 1100px 이하에서는 트레이를 하단 180px 영역으로 옮긴다.

[Sunsama의 timeboxing 안내](https://help.sunsama.com/docs/usage-guides/timeboxing/)는 소요시간을 먼저 정하고 작업을 달력에 끌어 놓는 흐름의 참고다. [Notion Calendar의 일정 관리 안내](https://www.notion.com/en-gb/help/manage-your-calendars-and-events)는 달력에서 직접 생성·이동·크기를 조절하는 익숙한 조작의 참고다. BLOKKY의 15분 단위, 근무시간 검증, 원자적 블록 분할은 이 제품의 규칙이며 외부 서비스 연결을 도입하지 않는다.

주간 격자와 날짜 시간표는 같은 Pointer Events 조작을 공유한다. 이동은 기존 길이를 유지하고, 나누기는 총 시간과 메모를 보존하며 뒤 블록을 미배치로 만든다. 저장소가 revision과 요청 재시도를 검증하는 단일 분할 명령을 처리한다. 편집 초안 복원은 자동 팝업 대신 이어서 편집으로 노출하고, 정상 저장 안내의 시각적 반복을 줄이되 오류·복구 행동은 유지한다.

## 2026-10-09 품질 목표 1단계

로드 실패에서도 기존 관리 백업 목록/검사를 제공하고, unavailable Store 전용 복구 명령을 사용한다. 손상 DB/WAL/SHM은 복구 자료로 보존하며 실패/중단 marker가 빈 저장소 자동 생성을 막는다. 건강한 Store의 epoch/미저장 보호를 전용 복구로 우회하지 않는다. SQLite 백업의 설정 대상은 근무 설정이고 개인 테마·캡처 단축키·OS 자동실행은 별도 보관이다.
손상 파일은 최초 RW open 자체가 WAL/SHM을 바꿀 수 있어 원본3파일의 임시 복사본 preflight를 startup과 복구 재검사에서 공유한다. 정상 WAL에 commit된 데이터도 포함해 검증한다. 원본 보존이 우선이며 이 추가 시작 I/O의 정식 성능 영향은 이후 측정한다.

Store 읽기 성공과 초안 읽기 성공을 분리한다. 초안 IPC 실패/JSON 해석 실패는 편집과 새 draft sequence 발급을 막는다. 읽은 sequence가 확인된 손상 초안만 사용자 확인 후 비울 수 있다. 운영 정보 조회 실패는 DB 손상으로 판정하지 않으며 재시도 상태를 표시한다.

분 경계·창 focus/visibility 복귀에서 오늘/계획 표시를 갱신하지만 사용자가 선택한 날짜는 자동 이동시키지 않는다. 편집·조합·모달·드래그 동안 전체 내용 재렌더를 보류한다. 일반 반복/알림/검색 등 원문 목표 확장은 [실행 계획](calendar-quality-action-plan-2026-10-09.md)의 이후 단계이며 이번 수정의 합격으로 처리하지 않는다.

## 2026-10-10 유동 배분 재설계

[재설계안](BLOKKY_redesign_intent_and_ux.md)과 [구현 계획](BLOKKY_redesign_implementation_plan.md)의 권장안 D1~D10을 사용자가 자율 착수로 승인했다.

- 작업은 미계획(`plan_date` 없음), 유동계획(`plan_date`+`flow_order`), 고정계획(`starts_at`), 완료된 유동 작업(날짜·순서 보존)으로 구분한다. 겹침 검사는 고정끼리만 한다.
- 유동 블록 위치는 저장하지 않는다. 날짜별 배치 기준 시각(`day_layouts.anchor`)과 순서·고정·휴식으로 `src/flow.ts`가 계산한다. 기준 시각은 오늘의 유동 작업 완료·일괄 완료·수동 재배치에서만 앞으로 갱신되며, 시간 경과·창 복귀·재시작·자정은 배치를 바꾸지 않는다.
- 추가·삭제·순서·고정 변경은 기존 기준 시각으로 다시 계산한다(D3). 공간이 부족하면 처음 들어가지 못한 블록부터 뒤를 모두 ‘배치되지 않음’으로 둔다(D4).
- 시간표 본문 드롭은 순서 삽입, 고정 레일 드롭과 범위 드래그는 시각 고정이다(D5·D6). 고정 작업은 완료해도 예약을 유지한다(D7).
- 근무시간 변경·정기 업무 생성에서 시각이 충돌한 작업은 같은 날짜의 유동 작업으로 둔다(D8·D9). 유동 작업의 완료 취소는 보존한 순서로 복귀한다(D10).
- 기존 v3 배치 작업은 모두 고정으로 이관하고, 이관 직전 `before-migration-<UUID>` 안전 백업을 남긴다(D1).
- 이 결정은 PRODUCT.md의 ‘자동 재배치 범위 밖’을 완료·수동 요청에 의한 기계적 재배치에 한해 대체한다. 추천·자동 이월·자동 분할은 여전히 범위 밖이다.

## 2026-10-10 React 전면 도입

사용자가 [시험 결과](react-spike-today.md)를 보고 전면 도입을 결정했다. 2026-10-08의 ‘React·캘린더 라이브러리 없이 시작’을 대체한다. 세부는 [React 도입 계획](BLOKKY_react_migration_plan.md) R1–R8.

- 화면은 React 19, 움직임은 `motion`, 드래그 감지는 `@dnd-kit/core`. 배치·저장 규칙의 기준은 계속 순수 모듈과 Rust다.
- 객체는 평면, 움직임은 물리적으로 표현한다. 오늘 화면은 블록 공간 하나와 오른쪽 상세로 구성하고 별도 순서 목록을 두지 않는다.
- 본문에 놓으면 순서, 레일에 놓으면 시각 고정이다. 고정 블록을 본문에 놓으면 고정을 풀고 그 순서에 넣는다.

## 2026-10-10 ‘배치되지 않음’ 폐지

사용자 지적: 작업은 미계획이거나 배치돼 있어야 하며 세 번째 상태는 이해할 수 없다. 오늘 화면에서 선반의 블록을 끌면 화면이 깜빡이고, 계획에서 선반의 블록을 시간표로 옮길 수 없었다.

- 원인: 선반 높이가 끄는 동안 바뀌면 문서가 짧아져 스크롤이 당겨지고, 포인터 아래 시간표가 움직여 놓을 자리가 번갈아 바뀌었다. 마지막 블록 중간보다 아래에 놓으면 순서 끝으로 들어가 다시 선반에 남았다.
- 결정: 근무시간에 들어가지 못한 유동 블록은 같은 순서로 근무 종료 뒤에 이어 놓는다(자정 뒤도 축을 늘려 표시). 자동으로 미계획으로 돌리는 안은 ‘시간 경과·재배치로 작업 상태를 바꾸지 않는다’는 원칙과 충돌해 택하지 않았다.
- 시간축은 근무 외 블록의 끝까지 늘어나며, 블록을 든 동안에는 저장된 배치와 미리보기 중 큰 쪽을 써서 줄어들지 않는다.
- 같은 요청으로 계획 상단 ‘시간 변경 검토’ 버튼을 없앴다. 남은 근무시간 초안은 날짜 팝업과 설정 저장 막대에서 다룬다. 배분 표시는 ‘7.5 / 8h’ 수치만 보이고 전체 문장은 접근성 이름에 둔다.
## 2026-10-11 레일 맞물림

외부 UX 비평: 본문 드롭은 순서, 레일 드롭은 시각 고정이라는 규칙이 조작 전에 드러나지 않는다. 10시 높이에 든 블록이 13:30에 놓이고, 주간 레일은 13px이라 겨누기 어렵다.

- 규칙(D5)은 유지한다. 순서를 바꾸다 시각이 고정되지 않게 하는 목적은 그대로다.
- 본문 위에서 든 블록은 순서가 정한 자리에 붙고 그 예상 시각을 보인다. 레일이 15분 눈금에 붙는 것과 같은 방식이다.
- 유동 블록 왼쪽에 레일을 향한 이를 둔다. 블록 왼쪽 끝을 레일 쪽으로 밀어 넣으면 맞물려 시각이 고정되고, 떼어 내면 풀린다. 포인터가 레일 위에 있어도 맞물린다. 거리는 같은 날 사용자 조정으로 일 24px·주 12px 밀기, 일 20px·주 10px 떼기다(처음 10px·6px은 너무 민감했다). 떼기는 붙이기보다 약간 쉽다.
- 고정 블록은 맞물린 채로 들려 위아래로 시각만 옮기고, 오른쪽으로 떼어 내야 순서로 돌아간다. 이전에는 걸쇠가 아닌 곳을 잡으면 곧바로 고정이 풀렸다.

## 2026-10-09 앱 내부 백업 관리

사용자 결정에 따라 파일 선택 대화상자 기반 가져오기·내보내기를 제거한다. 설정에서 자동 시간별/날짜별 백업과 직접 만든 백업을 한 목록으로 보여 주고, **지금 백업**은 같은 로컬 `backups` 폴더에 UUID 이름으로 생성한다. 목록은 유형·생성 시각·작업 수를 표시한다. 손상된 항목은 오류 이유와 함께 비활성화한다. 유효한 백업을 선택하면 전체·배치·완료 수를 확인한 뒤 같은 화면에서 데이터 교체를 확인하고 복원한다.

자동 시간별 24개·날짜별 30개 보존은 유지한다. 직접 만든 UUID 백업과 복원 전 안전 백업(`before-restore-<UUID>`)은 자동 정리하지 않는다. 외부 디스크 내보내기와 임의 파일 가져오기는 제품에서 제공하지 않는다. 미저장 초안 보호와 복원 전 현재 기록의 안전 사본을 유지한다.

외부 문서는 개발 판단 근거이며 런타임에는 외부 URL/API/폰트를 사용하지 않는다.

## 2026-10-09 기간 보기와 근무 모델

Google Calendar 공식 도움말의 일/주/월/사용자 지정 보기와 요일별 근무 시간 방식을 참고했다.
- https://support.google.com/calendar/answer/6110849?co=GENIE.Platform%3DDesktop&hl=en
- https://support.google.com/calendar/answer/7638168?hl=en

BLOKKY에서는 4주를 월과 통합하고 주/2주/월을 제공한다. 주는 시간 격자로 충돌과 빈 시간을, 2주는 날짜별 작업 제목으로 가까운 계획을, 월은 배치량·여유시간으로 업무 분포를 판단한다. 아래 추가 확장에 따라 우측 날짜 상세는 2주·월에서 유지하고 주는 넓은 격자를 사용한다.

근무는 요일별 기본 일정에 날짜 예외를 우선 적용한다. 근무 범위 밖과 이름 있는 반복 금지시간이 배치 불가 영역이며 해당 날짜에서 바로 조정할 수 있다. 휴가는 그 날짜를 비활성화하고, 조퇴는 종료 시각을 변경한다. 이미 배치된 작업과 충돌하면 영향을 먼저 보여주고 할 일함 이동에 동의해야 변경한다. 사용자가 확인한 주 40시간·5일은 비교 목표이며 자동 근태 측정이나 법정 근무 검증이 아니다.

## 2026-10-09 할 일함과 캘린더 조작 확장

사용자가 요청한 ‘담기 → 크기 정하기 → 배치하기’를 기존 네 테마 안에서 구현한다. 독립 할 일함은 날짜 없이 캡처할 공간이고 계획의 트레이는 배치할 작업을 고르는 공간이다. 기본 주간 보기에서 중복 날짜 상세를 걷어내고 격자 너비를 확보한다. 월·2주는 날짜 상세를 유지하며 1100px 이하에서는 트레이를 하단 180px 영역으로 옮긴다.

[Sunsama의 timeboxing 안내](https://help.sunsama.com/docs/usage-guides/timeboxing/)는 소요시간을 먼저 정하고 작업을 달력에 끌어 놓는 흐름의 참고다. [Notion Calendar의 일정 관리 안내](https://www.notion.com/en-gb/help/manage-your-calendars-and-events)는 달력에서 직접 생성·이동·크기를 조절하는 익숙한 조작의 참고다. BLOKKY의 15분 단위, 근무시간 검증, 원자적 블록 분할은 이 제품의 규칙이며 외부 서비스 연결을 도입하지 않는다.

주간 격자와 날짜 시간표는 같은 Pointer Events 조작을 공유한다. 이동은 기존 길이를 유지하고, 나누기는 총 시간과 메모를 보존하며 뒤 블록을 미배치로 만든다. 저장소가 revision과 요청 재시도를 검증하는 단일 분할 명령을 처리한다. 편집 초안 복원은 자동 팝업 대신 이어서 편집으로 노출하고, 정상 저장 안내의 시각적 반복을 줄이되 오류·복구 행동은 유지한다.

## 2026-10-09 품질 목표 1단계

로드 실패에서도 기존 관리 백업 목록/검사를 제공하고, unavailable Store 전용 복구 명령을 사용한다. 손상 DB/WAL/SHM은 복구 자료로 보존하며 실패/중단 marker가 빈 저장소 자동 생성을 막는다. 건강한 Store의 epoch/미저장 보호를 전용 복구로 우회하지 않는다. SQLite 백업의 설정 대상은 근무 설정이고 개인 테마·캡처 단축키·OS 자동실행은 별도 보관이다.
손상 파일은 최초 RW open 자체가 WAL/SHM을 바꿀 수 있어 원본3파일의 임시 복사본 preflight를 startup과 복구 재검사에서 공유한다. 정상 WAL에 commit된 데이터도 포함해 검증한다. 원본 보존이 우선이며 이 추가 시작 I/O의 정식 성능 영향은 이후 측정한다.

Store 읽기 성공과 초안 읽기 성공을 분리한다. 초안 IPC 실패/JSON 해석 실패는 편집과 새 draft sequence 발급을 막는다. 읽은 sequence가 확인된 손상 초안만 사용자 확인 후 비울 수 있다. 운영 정보 조회 실패는 DB 손상으로 판정하지 않으며 재시도 상태를 표시한다.

분 경계·창 focus/visibility 복귀에서 오늘/계획 표시를 갱신하지만 사용자가 선택한 날짜는 자동 이동시키지 않는다. 편집·조합·모달·드래그 동안 전체 내용 재렌더를 보류한다. 일반 반복/알림/검색 등 원문 목표 확장은 [실행 계획](calendar-quality-action-plan-2026-10-09.md)의 이후 단계이며 이번 수정의 합격으로 처리하지 않는다.

## 2026-10-10 유동 배분 재설계

[재설계안](BLOKKY_redesign_intent_and_ux.md)과 [구현 계획](BLOKKY_redesign_implementation_plan.md)의 권장안 D1~D10을 사용자가 자율 착수로 승인했다.

- 작업은 미계획(`plan_date` 없음), 유동계획(`plan_date`+`flow_order`), 고정계획(`starts_at`), 완료된 유동 작업(날짜·순서 보존)으로 구분한다. 겹침 검사는 고정끼리만 한다.
- 유동 블록 위치는 저장하지 않는다. 날짜별 배치 기준 시각(`day_layouts.anchor`)과 순서·고정·휴식으로 `src/flow.ts`가 계산한다. 기준 시각은 오늘의 유동 작업 완료·일괄 완료·수동 재배치에서만 앞으로 갱신되며, 시간 경과·창 복귀·재시작·자정은 배치를 바꾸지 않는다.
- 추가·삭제·순서·고정 변경은 기존 기준 시각으로 다시 계산한다(D3). 공간이 부족하면 처음 들어가지 못한 블록부터 뒤를 모두 ‘배치되지 않음’으로 둔다(D4).
- 시간표 본문 드롭은 순서 삽입, 고정 레일 드롭과 범위 드래그는 시각 고정이다(D5·D6). 고정 작업은 완료해도 예약을 유지한다(D7).
- 근무시간 변경·정기 업무 생성에서 시각이 충돌한 작업은 같은 날짜의 유동 작업으로 둔다(D8·D9). 유동 작업의 완료 취소는 보존한 순서로 복귀한다(D10).
- 기존 v3 배치 작업은 모두 고정으로 이관하고, 이관 직전 `before-migration-<UUID>` 안전 백업을 남긴다(D1).
- 이 결정은 PRODUCT.md의 ‘자동 재배치 범위 밖’을 완료·수동 요청에 의한 기계적 재배치에 한해 대체한다. 추천·자동 이월·자동 분할은 여전히 범위 밖이다.

## 2026-10-10 React 전면 도입

사용자가 [시험 결과](react-spike-today.md)를 보고 전면 도입을 결정했다. 2026-10-08의 ‘React·캘린더 라이브러리 없이 시작’을 대체한다. 세부는 [React 도입 계획](BLOKKY_react_migration_plan.md) R1–R8.

- 화면은 React 19, 움직임은 `motion`, 드래그 감지는 `@dnd-kit/core`. 배치·저장 규칙의 기준은 계속 순수 모듈과 Rust다.
- 객체는 평면, 움직임은 물리적으로 표현한다. 오늘 화면은 블록 공간 하나와 오른쪽 상세로 구성하고 별도 순서 목록을 두지 않는다.
- 본문에 놓으면 순서, 레일에 놓으면 시각 고정이다. 고정 블록을 본문에 놓으면 고정을 풀고 그 순서에 넣는다.

## 2026-10-10 ‘배치되지 않음’ 폐지

사용자 지적: 작업은 미계획이거나 배치돼 있어야 하며 세 번째 상태는 이해할 수 없다. 오늘 화면에서 선반의 블록을 끌면 화면이 깜빡이고, 계획에서 선반의 블록을 시간표로 옮길 수 없었다.

- 원인: 선반 높이가 끄는 동안 바뀌면 문서가 짧아져 스크롤이 당겨지고, 포인터 아래 시간표가 움직여 놓을 자리가 번갈아 바뀌었다. 마지막 블록 중간보다 아래에 놓으면 순서 끝으로 들어가 다시 선반에 남았다.
- 결정: 근무시간에 들어가지 못한 유동 블록은 같은 순서로 근무 종료 뒤에 이어 놓는다(자정 뒤도 축을 늘려 표시). 자동으로 미계획으로 돌리는 안은 ‘시간 경과·재배치로 작업 상태를 바꾸지 않는다’는 원칙과 충돌해 택하지 않았다.
- 시간축은 근무 외 블록의 끝까지 늘어나며, 블록을 든 동안에는 저장된 배치와 미리보기 중 큰 쪽을 써서 줄어들지 않는다.
- 같은 요청으로 계획 상단 ‘시간 변경 검토’ 버튼을 없앴다. 남은 근무시간 초안은 날짜 팝업과 설정 저장 막대에서 다룬다. 배분 표시는 ‘7.5 / 8h’ 수치만 보이고 전체 문장은 접근성 이름에 둔다.
## 2026-10-11 레일 맞물림

외부 UX 비평: 본문 드롭은 순서, 레일 드롭은 시각 고정이라는 규칙이 조작 전에 드러나지 않는다. 10시 높이에 든 블록이 13:30에 놓이고, 주간 레일은 13px이라 겨누기 어렵다.

- 규칙(D5)은 유지한다. 순서를 바꾸다 시각이 고정되지 않게 하는 목적은 그대로다.
- 본문 위에서 든 블록은 순서가 정한 자리에 붙고 그 예상 시각을 보인다. 레일이 15분 눈금에 붙는 것과 같은 방식이다.
- 유동 블록 왼쪽에 레일을 향한 이를 둔다. 블록 왼쪽 끝을 레일 쪽으로 밀어 넣으면 맞물려 시각이 고정되고, 떼어 내면 풀린다. 포인터가 레일 위에 있어도 맞물린다. 거리는 같은 날 사용자 조정으로 일 24px·주 12px 밀기, 일 20px·주 10px 떼기다(처음 10px·6px은 너무 민감했다). 떼기는 붙이기보다 약간 쉽다.
- 고정 블록은 맞물린 채로 들려 위아래로 시각만 옮기고, 오른쪽으로 떼어 내야 순서로 돌아간다. 이전에는 걸쇠가 아닌 곳을 잡으면 곧바로 고정이 풀렸다.
- 검토 후 택하지 않은 안: 빈 시간 드롭을 고정으로 바꾸기(나중에 하려고 끈 블록이 고정됨), 놓은 뒤 ‘걸기’ 제안(예방이 아닌 복구), 든 동안 주간 레일 넓히기·포인터 높이의 레일 미리보기(맞물림이 같은 역할을 하며 표시가 늘어남).

## 2026-10-11 천장과 끌려 올라감

## 2026-10-11 맞물림의 움직임 예산

## 2026-10-11 오늘은 대시보드, 하루 편집은 계획의 일 보기

사용자 정정: 오늘 탭은 오늘 할 일의 대기열을 확인하는 대시보드이지 하루 계획 편집 몰입 화면이 아니다.

## 2026-10-11 삭제 확인 창 대신 휴지통

사용자 지적: ‘삭제할까요’가 Windows 기본 확인 창으로 뜬다. 확인 창 대신 일정 기간 뒤 자동으로 비워지는 휴지통을 둔다.

- 삭제(목록·편집기·블록 메뉴)는 질문 없이 작업을 휴지통으로 옮긴다. 저장소는 같은 `tasks` 행에 `deleted_at`(UTC, 초 단위 고정 형식)을 기록하고 스냅숏은 휴지통 항목을 `tasks`가 아닌 `trash`로 따로 보낸다. 그래서 배치·겹침 검사·정기 업무·하루 비우기·지난 작업 목록은 휴지통을 보지 않는다.
- 보존 기간은 30일(`TRASH_RETENTION_DAYS`). 앱 시작 시 저장소를 열 때와 시간별 백업 주기에서 지난 항목을 지운다. 개별 영구 삭제는 바로, ‘휴지통 비우기’만 같은 자리 확인을 거친다. 휴지통이 안전망이므로 다른 단계의 확인은 두지 않는다.
- 복원은 날짜·순서·고정 시각·완료 상태를 되돌린다. 유동 작업은 원래 순서 번호 자리에 끼우고 뒤 순서를 한 칸씩 민다. 고정 작업의 시각이 다른 고정 작업·휴식·근무 외와 겹치면 실패시키지 않고 같은 날짜의 유동 작업(순서 끝)으로 넣으며 안내 문구로 알린다(D8·D9와 같은 규칙). 미계획으로 돌리는 안은 날짜를 잃어 택하지 않았다.
- 저장소 v5: 기존 DB에는 열 추가만 하는 이관이며, 이전처럼 직전에 `before-migration-<UUID>` 안전 백업을 남긴다. 이전 실행 파일은 v5를 지원하지 않는 버전으로 거부해 휴지통을 일반 작업으로 되살리거나 버리지 않는다. 백업·복원·복구는 휴지통 항목을 함께 옮기고, 백업 검사의 작업 수는 휴지통을 제외한다.

## 2026-10-11 고정 변경이 배치를 무효로 만들 때

사용자 지적: 고정 일정과 유동 일정 사이 순서를 바꾸면 유동 블록이 빈 시간이 없는 곳으로 튕겨 나가거나 떨린다. 고정화·고정 블록 이동이 공간 배치를 무효로 만들 때의 반응을 정해야 한다.

- 원인: 레일 위에서 고정 블록을 끄는 동안 15분 눈금마다 유동 배치를 다시 계산해 바로 보였다. 순서를 지키고 쪼개지 않으므로 한 눈금 차이로 이웃이 고정 블록 앞뒤를 1–2시간씩 오갔다(예시 데이터: 워크숍 13:45↔14:00에서 ‘분리망 배포’가 14:45↔13:00). 경계에서 손이 조금만 흔들려도 떨림이 됐다.
- 반응 시점: 머무르면 반영한다. 레일 위 시각(고정 블록 이동, 맞물린 유동 블록)과 길이 조절은 같은 값에 0.2초 머문 뒤에야 이웃이 자리를 옮긴다. 지나가는 동안에는 이웃이 그대로이고, 든 블록과 조절 중인 블록 자신만 손을 따른다. 레일을 벗어나거나 본문 순서·날짜·미계획으로 옮길 때와 놓을 때는 바로 반영한다.
- 밀림 규칙: 현행 유지. 들어가지 못한 유동 블록은 고정 블록 뒤의 들어갈 수 있는 첫 빈 시간으로 가고 뒤 블록도 순서대로 따른다. 앞지르기로 빈 시간을 채우는 안은 ‘다음 = 순서 첫 블록’을 깨고, 고정 경계 분할은 자동 분할 범위 밖이라 택하지 않았다.
- 공간 부족: 막지 않는다. 근무 종료 뒤에 이어 놓는 2026-10-10 결정을 유지하고, 표현을 다음처럼 정한다.
  - 평소: 근무 외 시간은 종료선 아래 회색 띠, 그곳의 유동 블록은 점선 테두리, 배분 옆 ‘근무 외 Nh’(기존).
  - 든 동안: 이번 변경으로 근무 외로 *새로* 밀리는 블록만 점선을 `--color-overdue`로 바꾸고, 든 복사본 위에 ‘근무 외 N개’를 같은 색 바탕으로 띄운다. 이미 근무 외였던 블록은 세지 않는다. 값은 머무름이 반영된 미리보기 기준이다.
  - 놓은 뒤: 화면 읽기 안내 ‘N개가 근무 외로 밀렸어요’. 보이는 경고·확인은 두지 않는다.

## 2026-10-11 미계획 작업대·도마·전역 검색

사용자와 합의한 인계 문서: [docs/BLOKKY_workbench_search_handoff.md](BLOKKY_workbench_search_handoff.md). 정책은 PRODUCT.md 같은 날짜 절을 따른다. 아래는 구현에서 정한 해석이다.

- 저장소 v6. `tasks`에 `proto`(0/1), `pile_id`(NULL = 투입구), `pile_order`를 더하고 더미 순서는 `piles(id, position)`에 둔다. 투입구는 행이 없는 기본 더미로 항상 맨 앞이다. 좌표는 저장하지 않는다. 모든 쓰기 뒤 Rust가 빈 더미를 지우고 번호를 다시 매기며, 스냅숏 검증은 ‘미완료 미계획 작업만 더미 위치를 가진다’는 형태를 강제한다.
- 프로토는 0→1로 돌아가지 않는다. 날짜 배치·길이 변경·명시적 길이 확정(`sized`)에서만 풀린다.
- 이관: v5 이하의 미완료 미계획 작업은 이전 화면 목록 순서(식별자 순)로 투입구에 쌓는다. 새로 담는 일은 맨 위로 들어가지만, 이관 직후에는 사용자가 보던 목록이 그대로 보이게 하는 쪽을 택했다. 이전 버전 백업은 읽을 때 같은 규칙으로 투입구 순서를 만든다.
- 동작: `place_unplanned`(여러 카드를 기존·새 더미의 위치로; 끼우기·새 더미·합치기·끌어서 돌려보내기 공통), `move_pile`, `ship_flow`(여러 블록을 순서대로 그날 순서 끝에), `split_pieces`(도마 확정). 기존 `split`은 도마로 대체했다.
- 날짜 기둥: 오늘은 근무일이 아니어도 포함한다(지금 할 일을 싣는 자리). ‘기존’ 막대 하나로 이미 실린 양을 보이고, 근무 외 분량은 실제 하루 배치에서 계산해 휴식·고정 사이 단편화도 반영한다.
- 고정 블록 쪼개기: 조각이 원래 시작 시각부터 이어서 고정된다. 합계를 유지하면 항상 들어가고, 늘려서 다른 고정 작업과 겹치면 확정을 거부한다. 유동으로 자동 전환하는 안은 사용자가 정한 시각을 말없이 바꾸므로 택하지 않았다.
- 오늘·계획의 미계획 칸에 끌어 놓은 일은 투입구 맨 위다. 더미가 보이지 않는 곳에서 ‘놓은 자리’를 더미 위치로 해석하면 예측할 수 없다.
- 날짜 없는 완료 보관 목록은 미완료로 되돌리기·삭제·보관 목록 비우기(휴지통으로)를 제공한다. 휴지통이 안전망이므로 비우기에는 확인을 두지 않는다.
- 검색은 이미 불러온 스냅숏 안에서 찾는다. 저장소 질의를 두지 않아 저장 구조 변경이 없다.

## 2026-10-11 요청 재시도 기한과 처리 기록 정리

아래의 시간 검사 순서·미래 시각 거절·만료 복구 정책은 2026-10-12 결정으로 보완한다.

- 사용자가 승인한 재시도 기한은 최초 생성부터 30일이다. `Command.issued_at`은 Unix 밀리초이며 큐 재시도·담기·날짜 블록·보관 초안에서 같은 요청 식별자와 함께 유지하고 요청 해시에 포함한다. 정확히 30일이 된 요청, 미래·잘못된 시각, 시각 없는 이전 초안은 `expired`로 거절한다. 현재 시각으로 자동 갱신하지 않는다.
- 저장소 v7의 `receipts`는 식별자·SHA256 해시·서버 수신 시각 `accepted_at`만 담는다. 제목·메모·명령 본문을 보관하지 않는다. 수신 시각 인덱스로 앱 시작과 기존 시간별 유지보수에서 30일 지난 기록을 지우며 새 타이머를 만들지 않는다. v6 이하 처리 기록은 이관 시각을 한 번 부여한다. v6 더미에는 이전 목록용 순서 보정을 실행하지 않는다.
- 삭제와 `meta.receipt_cutoff` 갱신은 한 트랜잭션이다. 기준 시각은 감소하지 않고, 그 시각 이하에 발급된 요청은 처리 기록 조회 전에 거절한다. PC 시계를 앞당겨 기록을 지운 뒤 되돌려도 오래된 요청을 다시 실행하지 않는다. 시계를 크게 되돌려 현재 시각이 기준 이하가 되면 PC 시각을 확인하라는 `clock` 오류를 보인다. 기존 백업 복원은 요청 세대(epoch)를 바꾸므로 처리 기록과 기준 시각을 함께 초기화할 수 있다.
- 만료 복구는 기존 ‘저장된 내용 확인’ 동작이다. 최신 기록을 불러오는 데 성공한 뒤 해당 요청의 캡처 식별자만 비우고 입력은 보존한다. 사용자가 다시 저장해야 새 요청을 만들며 자동 재제출·자동 종료 저장은 오래된 요청을 새 요청으로 바꾸지 않는다. 새로 입력한 다른 초안의 식별자는 건드리지 않는다.

## 2026-10-12 저장 결과 확인과 초안·재시도 분리

- 요청 식별자·내용 해시와 데이터 변경을 같은 트랜잭션으로 기록하는 중복 방지, 복원 세대(epoch), 수정 버전 검사는 유지한다. 같은 세대의 처리 기록이 남아 있으면 내용 일치를 먼저 확인하고 최신 스냅숏으로 성공을 알린다. 이미 처리한 요청은 만료·PC 시계 보정 때문에 다시 실행하거나 실패시키지 않는다.
- 네이티브 저장의 최종 판단은 Rust 저장소가 맡는다. 화면의 시각 검사로 저장소의 처리 기록 확인을 가로막지 않는다. 새 요청에는 최대 5분의 미래 시각 차이를 허용한다. 처리 기록 시각은 수신 시각과 요청 시각 중 큰 값으로 기록해, 허용한 미래 요청이 정리 뒤 다시 실행되는 틈을 막는다. 처리 기록 30일 보관과 감소하지 않는 정리 기준은 유지한다.
- 입력 초안과 이미 저장을 시도한 요청은 별개다. 입력을 바꾸더라도 결과가 확정되지 않은 요청의 식별자·내용·생성 시각을 유지한다. 늦은 저장 성공은 해당 요청의 입력만 정리하고 이후 편집은 보존한다. 전송 전 요청을 초안에 보관하고, 보관 실패 시 전송하지 않는다.
- 보관 초안을 불러올 때 처리 기록을 조회해 확인된 저장 성공은 자동으로 반영한다. 시각 필드가 없는 구버전 요청은 기존 해시를 보존해 확인한다. 처리 기록 조회 자체는 미처리 요청을 실행하지 않는다.
- ‘저장된 내용 확인’은 최신 기록을 조회하며, 저장 여부를 확정할 수 없는 만료 요청을 자동 해제하지 않는다. ‘입력 유지하고 수정’에서 과거 저장 여부를 확인할 수 없고 다음 저장이 중복을 만들 수 있음을 확인받은 경우에만 해당 요청을 해제한다. 확인은 자동 재전송을 하지 않으며 새 저장에는 사용자의 다음 저장 동작이 필요하다.

## 2026-10-12 미계획 드롭 표시의 연속성

- 더미 이동의 드래그 복사본은 저장 결과를 기다리는 동안 놓은 위치에 남고, 저장된 실제 목적지로 이동한 뒤 카드 표시로 바뀐다. 고정 시간 타이머나 기존 드래그 원본 노드의 위치로 성공한 드롭을 마무리하지 않는다.
- 전환 중에는 운반한 원본·목적지 카드가 복사본과 겹쳐 나타나지 않게 한다. 목적지 카드는 별도의 등장·위치 애니메이션을 중복 실행하지 않으며 주변 카드의 기존 자리 이동은 유지한다. 저장 실패·취소는 원래 위치로 돌아가고, 모션 감소 설정에서는 이동을 생략하되 저장 결과를 기다리는 표시는 유지한다.
- 더미 이동을 위한 별도 낙관적 저장소나 새 의존성은 추가하지 않는다. 실제 저장 결과와 DOM 목적지를 연결하며, 날짜 기둥처럼 착지 카드가 없는 곳에서는 놓은 위치에서 복사본을 정리한다.
- 드래그 중 원본이 사라져 라이브러리가 착지 애니메이션을 건너뛰더라도 저장과 상태 정리는 완료한다. 애니메이션·대체 경로·화면 해제가 같은 저장 Promise를 공유해 중복 실행을 막는다.

## 2026-10-13 한 화면과 몰입

사용자가 탭 역할의 중복(준비가 세 곳, 날짜가 세 곳)을 지적하고 상용 플래너 조사([기록](commercial-planner-research-2026-10-13.md))를 거쳐 실험을 승인했다. 브랜치 `exp/one-screen`에서 [구현 계획](one-screen-plan.md)의 1–5단계로 만들고, 사용자가 “큰 틀에서 채택”한 뒤 섹션별 감사·다듬기를 거쳐 master에 합쳤다. 이 결정은 위 절들의 탭 구성(오늘·계획·준비·검색·설정 레일)과 계획 드로어를 대체한다.

- 탭을 없애고 화면을 둘로 둔다. 작업 화면(왼쪽 준비 도크 + 캘린더)이 시작 화면이고, 몰입 화면은 오늘을 하는 곳이다. 설정은 톱니, 검색은 Ctrl K 오버레이. 준비 목록과 날짜를 한 화면에 한 번씩만 보이기 위해서다.
- 가공과 배분은 도크 폭으로 나눈다(좁게·넓게·접힘). 폭은 사용자의 명시적 조작으로만 바뀌고 기기에 기억한다. 검색 결과로 넓은 도크를 열어도 저장된 폭은 바꾸지 않는다. 준비 탭의 날짜 기둥 5일은 옆 캘린더가 맡으므로 없앴다.
- 준비 메뉴는 화면 이름이 아니라 카드에서 열렸는지로 고른다.
- 단축키는 한 글자 키를 `e.code`로 판정하고 입력·한글 조합·수정키·이미 처리된 키·열린 대화상자·메뉴·컴포저에서는 받지 않는다. WCAG 2.1.4에 따라 ? 목록의 ‘한 글자 단축키’ 스위치로 끌 수 있다.
- 몰입에서 ‘시간 경과 지연 표시 없음’ 원칙을 유지한다(사용자 선택). 시계 기준의 지금 블록·남은 시간·초과는 두지 않고, ‘다음’은 시계와 무관한 남은 첫 유동 블록이다. 연장은 15분 스냅에 맞춰 +15분만 둔다. 예상 끝 시각은 저장된 계획에서 계산해 시계가 흘러도 바뀌지 않는다.
- 넘침 해결 ‘준비로’는 넘친 유동 블록을 그날 순서대로 선반 맨 위에 한 번에 놓는다. 기존 선반 놓기 명령을 그대로 쓰고 고정 블록과 지난 날짜는 건드리지 않는다.
- 작업 화면의 편집기는 새 팝오버를 만들지 않고 같은 모달 대화상자를 블록 옆에 놓는다. 닫기 확인·초안·충돌 처리를 건드리지 않기 위해서다.
- 항상 위 타이머 창은 만들지 않는다. 시계 표시가 없으면 몰입 카드의 반복일 뿐이고, 늘 떠 있는 창은 시간 압박으로 읽히기 쉽다. 필요해지면 전역 단축키나 트레이 메뉴를 먼저 검토한다.
- 디자인 체계의 이름을 ‘평면 블록, 물리적 움직임’으로 정하고(사용자 선택) DESIGN.md를 지금 화면 기준으로 다시 썼다. 2026-10-08의 ‘확정 B/D 기본안’ 시각 체계 결정은 색·글꼴·반경 토큰으로 이어지지만, 레일과 화면 구성은 이 절이 대체한다.
- 접근성은 실용 기준(키보드 완결, 네 테마의 본문 4.5:1·조작 단서 3:1, 화면 읽기는 최선)이다(사용자 선택). 입력란 경계 3:1의 전면 적용은 결정 대기다.

## 2026-10-13 지나가는 곳의 형태

사용자 지적: 들고 지나가는 영역마다 블록이 그 영역의 크기로 바뀌어 이동이 ‘깜빡이는’ 것처럼 보인다. 지나가는 동안은 형태를 유지하고, 가져다 댔을 때만 바뀌도록 문턱이 필요하다.

- 든 블록의 형태(폭·높이·밀도·고정 모양)와 그 영역의 미리보기(비켜 주기·빈자리)·강조(hot·레일 걸림·시각 표)는 손이 그 영역에 ‘도착’한 뒤에만 바뀐다. 도착은 영역에 들어와 70ms가 지나고 손 속도가 3px/프레임 아래일 때, 또는 속도와 무관하게 260ms 머물렀을 때다. 멈춘 손의 속도는 40ms 시간 상수로 빠르게 줄어 멈춘 뒤 약 0.1초 안에 도착한다.
- 지나가는 동안 레일 눈금 맞춤도 하지 않고, 오류·근무 외 같은 손 아래 자리의 안내도 띄우지 않는다. 놓기 판정은 그대로 손 아래 자리를 따르므로 지나가다 놓아도 그 자리로 가고, 착지 애니메이션이 형태를 맞춘다.
- 영역 안의 레일·본문 전환(걸쇠)은 기존의 물기·놓기 문턱이 맡으므로 이 문턱을 더하지 않는다.

## 2026-10-13 계획 막대 정리

사용자 판단: 작업 화면의 ‘정기 업무’, ‘N일 비우기’ 버튼은 불필요하다.

- 계획 막대에는 주 요약만 둔다. 정기 업무는 톱니(설정)의 정기 업무 절에서 그대로 다룬다.
- 하루 비우기는 화면 조작에서 뺐다. 날짜의 블록은 하나씩 또는 여러 선택으로 준비에 돌리고, 넘친 블록은 날짜 머리의 ‘준비로’가 맡는다. 저장소의 `clear_day` 명령과 생성 이력의 중복 방지는 그대로 두어 다시 필요해지면 조작만 붙인다.

## 2026-10-13 몰입을 위 막대 맨 앞으로

사용자 지적: 몰입의 중요성에 비해 오른쪽 끝 묶음(검색·?·톱니 사이)에 있어 도구처럼 보인다. 네 안(막대 맨 앞, 오늘 날짜 머리, ‘작업 | 몰입’ 전환 쌍, 맨 앞에 크게) 중 사용자가 ‘막대 맨 앞’을 골랐다.

- 화면 전환 버튼을 로고 바로 다음에 둔다. 작업 화면에서는 primary ‘몰입’, 몰입·설정에서는 같은 자리의 ‘작업 화면’이다. 오른쪽 묶음에는 검색·?·톱니만 남는다.
- 크기와 색은 그대로다(위 막대의 action 색 버튼은 여전히 몰입 하나). 긴 기간 제목이 줄어도 이 버튼은 줄지 않는다.

## 2026-10-13 좁은 달력 칸

사용자 지적: 작은 화면에서 넓은 도크를 편 채 2주·월을 보면 달력 칸의 글자가 한두 글자씩 줄바꿈되며 칸 밖으로 넘친다(‘오늘’ 알약 포함). 같은 화면에서 날짜 패널 오른쪽이 비어 있었다.

- 원인 1: 두 열을 `minmax(280px, 비율fr)`로 나눠, 한쪽이 최소 폭에 걸리면 남은 fr 합이 1보다 작아져 줄을 다 채우지 못했다(CSS 그리드는 합이 1 미만이면 1로 나눈다). 첫 열을 `clamp(280px, 비율 × 폭, 폭 − 296px)`, 둘째 열을 `1fr`로 바꿔 저장된 비율이 낡아도 늘 채운다. 몰입의 두 열도 같은 방식이다.
- 원인 2: 칸 내용이 최소 폭을 전제했다. 칸을 크기 컨테이너로 두고 자기 폭에 따라 줄인다(58px: 한 줄 제목·짧은 시간·근무 외 글자 생략, 38px: ‘오늘’은 밑줄, 30px: 글자 없는 블록·월은 막대만). 낱말을 글자 단위로 쪼개는 줄바꿈은 두지 않는다.
- 넓은 도크의 폭은 사용자가 바꿀 때만 바뀐다는 원칙을 지키려고 도크는 줄이지 않았다.

## 2026-10-13 편집기의 ‘초안 버리기’ 제거

사용자 지적: 블록 편집기 본문의 ‘초안 버리기’가 어색하다. 첫 커밋부터 있던 버튼이 React 이전에서 그대로 옮겨졌을 뿐 남길 근거가 기록돼 있지 않았다.

- 같은 일을 닫기 확인의 ‘변경 버리기’가 한다(× 또는 Esc → 저장하고 닫기·초안으로 남기고 닫기·변경 버리기). 본문 중간의 글자 버튼, 별도 확인 창, 내부 용어 ‘초안’이 모두 어긋나 버튼을 없앴다.
- ‘저장 안 됨’ 표시, 닫기 확인, 상태줄의 ‘이어서 편집’, 보관 초안을 읽지 못했을 때의 ‘보관 초안 버리기’는 그대로다.

## 2026-10-14 기다림

사용자가 ‘내 차례가 아닌 일’의 상태를 버튼·칩·대화상자로 드러내는 안(2026-10-13)을 “상태를 그대로 버튼으로 노출한 것”이라며 거절했고, 사용 흐름(트리거를 정해 밀기 → 충족 확인 → 블록으로 되살아남 → 배치·실행)에서 다시 출발해 [시안](https://claude.ai/artifact/8tMQLdmANKyxhRTVc9uJ34)을 확정했다. 묶음 모션은 상용 제품 다섯 안 중 B(iOS 알림 묶음)를 골랐다.

- 상태는 기하로 드러낸다: 오른쪽 띠라는 자리, 트리거 꼬리표, 같은 트리거의 쌓임. 상태 전환은 끌기·B·꼬리표 떼기 같은 직접 조작이다. 이름은 ‘대기’ 대신 ‘기다림’이다(몰입의 ‘남은 블록 대기열’과 겹치지 않게).
- 캘린더에 원래 자리 흔적을 남기지 않는다. 언제 돌아올지 모르는 시간을 붙잡아 두는 것이 어색했기 때문이다.
- 트리거는 상대+무엇 글 또는 날짜 하나다. 날짜가 와도 모양(진한 꼬리표, 띠 밖으로 조금)만 바뀌고, 충족은 늘 사람이 확인한다. 기다림의 체크는 ‘트리거 충족’이지 ‘작업 완료’가 아니므로 네모 손잡이로 둥근 완료 체크와 모양을 나눈다.
- 블록 하나를 그대로 밀고, 되살릴 때 다음 행동으로 이름을 바꾼다. 되살아난 블록은 선반 맨 위(판은 들어옴 맨 위)로 간다. 기존 ‘준비로’ 규칙과 같다.
- 기다리는 색은 조용하다(“트리거가 만족될 때까지 구석에 있을 녀석들”). 충족된 것만 강조색을 쓴다.
- 착수 결정(사용자, 추천대로): 전부 단계별 커밋으로 구현한다. 띠는 작업 화면에만 두고 몰입에서는 ‘다음’ 카드의 B만 둔다. 하나짜리 블록도 네모 손잡이만 충족이며, 꼬리표 글자를 누르면 그 자리에서 트리거를 고친다(시안에는 고치는 방법이 없었다).
- 구현에서 정한 것: 저장은 v10(작업 열 `wait_for`·`wait_until`·`wait_since`, 동작 `wait`·`revive`). 고정 블록도 ‘준비로’처럼 밀 수 있고 시각이 풀린다. 띠 폭은 도크처럼 사용자가 바꿀 때만 바뀌며 기본은 펼침이다. 밀기·충족에는 몇 초짜리 되돌리기를 둔다. 띠 안에서 글자 키는 초성 건너뛰기다. 트리거 수정은 F2.
- 1440px에서 좁은 도크 + 펼친 띠 옆 주 보기가 가로 스크롤 없이 들어가도록 주 칸 최소 폭을 118→110px로 줄였다. 더 좁은 창에서 띠를 펼치면 주 보기는 가로로 스크롤한다. 줄일지는 띠를 접는 사용자의 몫이다.

## 2026-10-15 레일은 본문 쪽에서만 물린다

사용자 제안: 레일 밖에서 안으로(왼쪽→오른쪽) 들어올 때는 고정되지 않고, 레일 안쪽에서 레일로(오른쪽→왼쪽) 밀 때만 걸쇠가 걸려야 한다. 레일이 하루 칸 왼쪽 끝에 있어서, 왼쪽 준비 도크나 주 보기의 왼쪽 날에서 끌어온 블록이 레일 위를 지나며 멈추면 순서에 넣으려던 블록이 시각 고정으로 놓였다.

- 이는 레일을 향해 블록 왼쪽에 있으므로, 레일을 넘어 들어온 블록은 레일을 지나칠 뿐이다. 블록 왼쪽 끝이 그날 본문(유동 블록이 서는 선)까지 완전히 들어온 뒤에야 기존 물기 문턱(일 24px·주 12px)이 적용된다. 포인터가 레일 위에 있으면 물리던 경로도 같은 조건을 따른다.
- 순간 이동 방향이 아니라 이번 드래그의 경로로 판정한다. 방향의 부호는 손 떨림과 대각선 이동에서 계속 바뀌어 걸쇠가 깜빡이기 때문이다. 그날을 벗어나면 준비가 풀리고, 다시 본문에 들어와야 한다.
- 고정 블록은 자기 날에서는 처음부터 물린 채 들리고, 그 날의 놓기 문턱도 그대로다. 다른 날로 옮기면 그날 레일에 다시 밀어 넣어야 고정된다(사용자 선택). 지금까지는 오른쪽 날로 옮길 때만 레일에 우연히 다시 물렸다.
- 레일 홈의 옅은 파랑은 든 동안 모든 날에 켜지던 것을, 밀어 넣을 수 있는 날에만 켠다. 블록이 켜진 레일을 그냥 지나가면 고장처럼 보이기 때문이다.

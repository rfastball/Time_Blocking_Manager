# BLOKKY 유동 배분 재설계 구현 계획

**작성일:** 2026-10-10
**입력:** [재설계안](BLOKKY_redesign_intent_and_ux.md), 현재 코드(`ec3351f`), [PRODUCT.md](../PRODUCT.md), [구현 결정](decisions.md), [검증 범위](test-policy.md)
**성격:** 재설계안의 합의 사항을 현재 구조 위에서 구현하는 순서와 경계. 재설계안이 후속 검토로 남긴 항목은 §2에서 권장안을 붙여 확인을 요청한다.

## 1. 현재 구현과 재설계안의 차이

| 영역 | 현재 (`ec3351f`) | 재설계 목표 |
|---|---|---|
| 배치 상태 | `starts_at` 유무 하나로 미계획/배치 구분. 배치된 모든 작업이 정확한 시각을 가짐 | 미계획 / 유동계획(날짜·순서·배분량) / 고정계획(날짜·시각) / 완료된 유동 작업 |
| 위치 결정 | 사용자가 드래그로 시각을 직접 지정. Rust가 겹침을 거부 | 유동 블록의 위치는 배치 결과. 고정·휴식을 피해 순서대로 놓임 |
| 완료 | `completed` 플래그만 바뀌고 블록은 제자리에 남음 | 유동 작업은 시간표 밖 완료 영역으로 빠지고 남은 일이 완료 시점부터 다시 놓임 |
| 시간 경과 | `agenda()`가 현재 시각으로 `current`/`overdue`를 계산해 ‘진행 중’·‘지남’ 배지 표시 | 현재선은 비접촉 표시선. 지남·지연 판정과 경고를 하지 않음 |
| 재배치 | 없음 (PRODUCT.md에서 자동 재배치는 범위 밖) | 완료·일괄 완료·수동 요청 때만 현재 기준으로 재배치 |
| 날짜 배정 | 날짜 칸 드롭 시 첫 빈 시각을 찾아 `starts_at` 지정 | 날짜에 놓으면 그날 유동 순서의 끝에 추가. 시각을 정하지 않음 |
| 공간 부족 | 겹침이면 저장 거부 | 들어가지 않는 블록은 그날 계획에 남고 ‘배치되지 않음’으로 보임 |

현재 코드에서 재설계에 영향을 받는 곳:

- **표시 모델:** `src/today.ts`(`agenda`의 시간 기반 상태), `src/placement.ts`(겹침 기준)
- **화면·조작:** `src/main.ts`(`todayHTML`, `taskRow`, `weekHTML`, `timelineHTML`, `planHTML`, `previewMutation`, `moveTask`, `overdue`, `inboxTasks`, 편집창 날짜·시각 필드, 우클릭 메뉴), `src/calendar-gestures.ts`(시각 기반 드롭), `src/availability.ts`(근무시간 변경 충돌 탐지)
- **문서:** PRODUCT.md의 “자동 재배치는 범위 밖”, “시간 경과 자동 완료 없음”, “블록 클릭은 상세”, decisions.md의 “재배치는 같은 ID의 시작 시각을 바꾼다”

## 2. 착수 전 확인할 결정 (권장안 포함)

재설계안 §13이 후속 설계로 남긴 질문 중 구현을 막는 항목이다. 권장안대로 진행하면 단계 1·2는 바로 착수할 수 있다.

| # | 질문 | 권장안 | 근거 / 대안 |
|---|---|---|---|
| D1 | 기존 `starts_at` 작업의 이관 | **모두 고정계획으로 이관**한다. 날짜별 ‘고정 해제’로 사용자가 유동 전환 | 사용자 결정을 몰래 바꾸지 않는다(§6.4). 대안: 오늘 이후의 미완료를 유동으로 전환. 화면은 깔끔하지만 사용자가 정한 시각을 잃는다 |
| D2 | 재배치 기준을 어떻게 유지할까 | **날짜별 배치 기준 시각(anchor)**을 저장하고, 위치는 `anchor + 유동 순서 + 고정·휴식`의 결정적 함수로 계산 | 블록별 계산 위치를 저장하는 방식보다 상태가 작고 재시작·복원 후에도 같은 모습이 나온다. 시간이 흘러도 anchor가 그대로라 블록이 움직이지 않는다 |
| D3 | 추가·삭제·순서 변경·고정 변경 시 재배치 범위 | **anchor를 유지한 채 다시 계산**한다. 편집 지점 앞의 블록은 움직이지 않는다. 현재 기준 재배치는 완료와 수동 요청에서만 한다 | §6.3의 ‘편집 반영’과 ‘현재 기준 재배치’를 구분한다. 오늘에 새로 추가한 블록이 현재선 위(과거)에 놓일 수 있으며 수동 재배치로 정리한다. 실사용에서 혼란이 크면 블록별 하한(floor) 시각을 추가한다 |
| D4 | 공간 부족 시 순서 | **엄격한 순서**를 적용한다. 처음 들어가지 못한 블록부터 뒤의 블록은 모두 ‘배치되지 않음’ | 뒤의 작은 블록이 앞질러 놓이면 순서를 몰래 바꾸는 것처럼 보인다(§4). 대안: 들어갈 수 있는 뒤 블록은 계속 놓는다 |
| D5 | 순서 변경과 시각 고정을 드래그에서 구분 | 시간표 본문 드롭은 **순서 삽입**(삽입선 표시)으로 한다. 시간 눈금 옆 **고정 레일**에 드롭하면 **시각 고정**(시각 미리보기·걸쇠 표시)이다. 키보드와 우클릭에는 ‘시각 고정…’, ‘앞으로/뒤로’를 둔다 | 순서 변경이 시각 고정으로 바뀌지 않게 한다(§4, §13). 대안: 보조키(Alt) 드래그. 숨은 조작이라 UI 원칙에 맞지 않는다 |
| D6 | 빈 시간 클릭·범위 드래그로 새 블록 만들기 | 클릭은 그 날짜의 **유동 작업**(30분, 순서 끝)을 만든다. 범위 드래그와 고정 레일 클릭은 **고정 작업**을 만든다 | 범위 드래그는 시각 의도가 분명하다. 클릭은 날짜 배정 의도로 해석한다 |
| D7 | 고정 작업의 완료 | 완료 표시만 하고 **예약 공간은 유지**한다. 공간 해제는 ‘고정 해제’나 시각 변경으로 명시적으로 한다 | §12: 완료와 예약 해제를 뭉뚱그리지 않는다. 조기 종료로 공간을 돌려받는 동작은 후속 단계에서 다룬다 |
| D8 | 근무시간 변경으로 충돌한 고정 작업 | 동의하면 **같은 날짜의 유동 작업으로 전환**한다(현재는 미계획 이동) | 날짜 배정을 보존한다. 유동은 근무시간과 충돌하지 않고 재배치된다 |
| D9 | 정기 업무 생성 시 충돌 | 시각이 충돌하면 **같은 날짜의 유동 작업**으로 만든다(현재는 미계획) | D8과 같은 이유. 정기 업무 자체는 고정 생성을 유지한다 |
| D10 | 완료 취소 시 복귀 위치 | 보존해 둔 **원래 유동 순서로 복귀**한다. anchor는 유지한다 | 과거 시각으로 되돌리거나 중복을 만들지 않는다(§9.4) |

## 3. 개념 모델

### 3.1 작업 상태

| 상태 | `plan_date` | `starts_at` | `flow_order` | `completed` |
|---|---|---|---|---|
| 미계획 | NULL | NULL | NULL | 0/1 (미계획 완료 목록 유지) |
| 유동계획 | 날짜 | NULL | 정수 | 0 |
| 완료된 유동 작업 | 날짜 유지 | NULL | 유지 (복귀용) | 1 |
| 고정계획 | `starts_at`의 날짜 | 날짜·시각 | NULL | 0/1 |

불변식(Rust `validate_task`/`validate_snapshot`이 검사):
- `starts_at`이 있으면 `plan_date == starts_at[..10]`이고 `flow_order`는 NULL이다.
- `flow_order`는 `plan_date`가 있고 `starts_at`이 없을 때만 존재한다. 같은 날짜 안에서 중복되지 않는다.
- 겹침 검사는 **고정 작업끼리만** 한다. 유동 작업은 근무시간·휴식·고정과 충돌하지 않는다.

### 3.2 날짜별 배치 기준

`day_layouts(date TEXT PRIMARY KEY, anchor INTEGER NOT NULL)`

- 행이 없으면 anchor는 그날 근무 시작이다. 미래 날짜와 과거 날짜는 이 기본값을 쓰며 현재 시각을 적용하지 않는다(§7).
- 오늘의 유동 작업 완료·일괄 완료·수동 재배치 때만 `anchor = max(기존 anchor, 확인 시각)`으로 갱신한다. 단조 증가라서 늦게 도착한 재시도가 기준을 과거로 되돌리지 않는다.
- 분 단위로 저장한다(15분 스냅 없음). 재설계안 §10 예시의 09:40·10:20 기준을 그대로 재현한다. 유동 블록의 표시 위치는 저장값이 아니므로 15분 검증 대상이 아니다.

### 3.3 배치 함수 (순수, `src/flow.ts`)

```
layoutDay(rule, fixed[], flow[] (flow_order 순, 미완료만), anchor)
  → { placed: {task, start, end}[], unplaced: {task, reason: 'total'|'contiguous'|'dayOff'}[] }
```

1. 막힌 구간 = 근무 외 + 휴식 + 고정 작업(완료 여부와 무관하게 예약 유지, D7).
2. `cursor = max(anchor, rule.start)`. 순서대로 `cursor` 이후의 가장 이른 연속 빈 구간에 놓는다. 분할하지 않는다.
3. 놓으면 `cursor = end`. 들어갈 곳이 없으면 그 블록과 뒤의 모든 블록을 `unplaced`로 보낸다(D4).
4. `reason`: 휴무일은 `dayOff`. 남은 빈 시간의 합이 배분량 이상이면 `contiguous`, 아니면 `total`이다(§12의 두 경우 구분).

Rust는 이 함수를 구현하지 않는다. 배치 결과는 저장하지 않는 표시값이고, 저장 경계는 상태·순서·anchor·고정 겹침만 검증한다. 같은 규칙이 두 곳에 생기지 않도록 하기 위해서다.

## 4. 저장소 변경 (스키마 v4)

### 4.1 마이그레이션

- 이관 직전에 `before-migration-<UUID>.sqlite` 안전 백업을 만든다(§8).
- `ALTER TABLE tasks ADD COLUMN plan_date TEXT; ADD COLUMN flow_order INTEGER;` 다음에 `CREATE TABLE day_layouts(...)`를 실행한다. 기존 행은 `UPDATE tasks SET plan_date=substr(starts_at,1,10) WHERE starts_at IS NOT NULL`로 고정계획이 된다(D1). `PRAGMA user_version=4`
- v3 실행 파일은 `1..=3`만 허용하므로 v4 DB를 열지 못한다. 다운그레이드 보호는 기존 방식을 그대로 쓴다.
- `check_database`는 `1..=4`를 허용한다. **`read()`는 버전에 따라 열을 선택한다.** v1~v3 백업을 검사·복원할 때 새 열이 없으므로 `plan_date`는 `starts_at`에서 파생하고 `flow_order`는 NULL로 읽는다. `restore`·`recover_from_backup`의 `INSERT INTO tasks VALUES(?1..?7)`은 열 이름을 명시하는 형태로 바꾸고 `day_layouts`도 복사한다.
- `BackupInspection`의 `scheduled`는 `plan_date`가 있는 작업 수로 바꾸고, 필요하면 `fixed` 수를 추가한다. UI 문구 ‘배치’는 유지한다.

### 4.2 명령 (`Action`)

기존 명령은 유지하되 의미를 좁히고, 상태 전이마다 명령을 하나씩 둔다. 모두 revision 검사와 receipt 재시도 규칙을 따른다.

| 명령 | 효과 |
|---|---|
| `AssignDate { id, expected_revision, date, before: Option<id> }` | 미계획·고정·다른 날짜 → 해당 날짜 유동. `before`가 없으면 순서 끝에 둔다. `starts_at`은 비운다 |
| `ReorderFlow { date, expected: Vec<TaskRevision> }` | 그날 미완료 유동 작업 전체를 새 순서로 다시 번호 매긴다. 집합이나 revision이 다르면 전체를 거부한다(`ClearDay`와 같은 방식) |
| `Fix { id, expected_revision, starts_at }` | 유동·미계획 → 고정. 고정끼리 겹침, 근무 외, 휴식을 검증한다 |
| `Unfix { id, expected_revision, before: Option<id> }` | 고정 → 같은 날짜 유동 |
| `CompleteFlow { date, items: Vec<TaskRevision>, at: String }` | 항목들을 한 번에 완료한다. `date`가 오늘이고 `at`의 날짜가 같을 때만 anchor를 `max(anchor, at)`으로 갱신한다. 과거·미래 날짜는 완료만 한다(§7). 단건 완료도 이 명령을 쓴다 |
| `Reflow { date, at: String }` | 상태를 바꾸지 않고 anchor만 갱신한다(수동 재배치) |
| `SetCompleted` | 고정·미계획 작업의 완료와 모든 완료 취소. 유동 작업의 완료 취소는 `flow_order`를 그대로 두고 복귀시킨다(D10) |
| `Update` | 제목·본문·소요시간만 바꾼다. 날짜·시각 변경은 위 전이 명령으로 분리한다 |
| `CreateScheduled` → `CreateFlow { id, title, date, duration }` / `CreateFixed { id, title, starts_at, duration }` | 시간표에서 만들 때 쓴다(D6) |
| `ClearDay` | 그날의 유동·고정 모두 미계획으로 돌린다. `expected_tasks`에 유동도 포함하고 `day_layouts` 행을 지운다 |
| `SetSchedule.move_conflicts` | 충돌한 고정을 같은 날짜 유동으로 전환한다(D8) |
| `EnsureRoutines` | 충돌하면 같은 날짜 유동으로 만든다(D9) |
| `Split` | 나눈 뒤 블록은 지금처럼 미계획으로 보낸다. 유동 원본은 순서를 유지한다 |

`at`은 클라이언트의 로컬 벽시계 `YYYY-MM-DDTHH:mm`이다. 서버는 형식과 날짜 일치만 검증한다. 미리보기 모드와 시험에서 시각을 주입할 수 있고, 재시도 시 receipt가 같은 결과를 보장한다.

## 5. 화면 변경

### 5.1 오늘

- **시간표:** 고정 블록은 걸쇠 아이콘과 접근성 이름 ‘시각 고정’을 가진다. 색이나 재질만으로 구분하지 않는다(§8.5). 유동 블록은 `layoutDay` 결과 위치에 그린다. 첫 미완료 유동 블록에 ‘다음’ 강조를 준다.
- **현재선:** 비접촉 표시만 한다. `agenda()`의 `current`/`overdue` 상태와 ‘진행 중’·‘지남’ 배지, `.overdue` 스타일, 편집창의 ‘지남’ 배지를 제거한다(§6.3, §11).
- **완료 영역:** 시간표 패널 상단, 시간축 바깥에 둔다. 기본은 접힌 한 줄(`완료 N`)이고, 펼치면 칩에 제목과 배분량을 보여 주며 다시 열기와 완료 취소를 제공한다. 배분량 합계를 ‘실제 작업시간’이라고 부르지 않는다.
- **배치되지 않음 영역:** 시간표 하단에 `unplaced` 블록을 그날 계획에 남긴 채 보여 주고 이유(`연속 공간 부족`/`공간 부족`/`휴무일`)를 표시한다. 경고색이나 자동 이월은 쓰지 않는다.
- **수동 재배치:** 오늘에만 시간표 헤더에 `지금 기준으로 다시 배치` 버튼을 두고, 현재 상태로 `HH:MM 기준`을 표시한다. 독촉 표시는 하지 않는다.
- **목록(오늘 순서):** 유동 순서와 고정을 시간 순으로 섞지 않는다. 고정은 시각 라벨, 유동은 순서대로 보여 준다. 체크박스는 단건 완료다. 다중 선택(Ctrl/Shift+클릭, Space)이 있으면 `선택한 N개 완료` 버튼으로 일괄 완료한다.
- **연속 완료 보호(§11):** 완료한 행은 포인터가 목록을 벗어나거나 몇 초가 지날 때까지 목록 자리에 취소선으로 남겨 행이 밀리지 않게 한다. 시간표 블록은 재배치 직후 짧은 시간 동안 클릭을 무시한다(`suppressGestureClick` 계열 재사용). 키보드 초점은 완료한 항목 자리 또는 같은 순번의 다음 항목에 둔다.
- **움직임:** 서버 응답 **이후에만** 흡입과 정착을 보여 준다(FLIP, 200ms 안팎). `prefers-reduced-motion`에서는 즉시 바꾼다. 낙관적 반영은 하지 않는다(§12, 저장 신뢰성).

### 5.2 계획

- **주간 격자:** 각 날짜 열에 같은 `layoutDay`를 쓴다. 미래 날짜의 anchor는 근무 시작이다. 열 하단에 배치되지 않은 블록 수를 표시한다.
- **드롭 규칙(D5):** 열 본문에 놓으면 삽입선을 보여 주고 `AssignDate`/`ReorderFlow`를 실행한다. 고정 레일(시간 눈금 쪽 띠)에 놓으면 시각 미리보기와 걸쇠를 보여 주고 `Fix`를 실행한다. 고정 블록을 본문에서 끌면 고정을 유지한 채 시각만 바뀐다. 2주·월의 날짜 칸, 주 헤더 날짜에 놓으면 그날 순서 끝에 `AssignDate`한다(현재의 ‘첫 빈 시각 찾기’를 대체).
- **크기 조절:** 유동·고정 모두 하단 손잡이로 배분량을 바꾼다. 유동은 겹침 거부 없이 재계산되고, 고정은 기존 겹침 검증을 유지한다.
- **용량:** 날짜 요약과 월 점유 막대는 `유동 미완료 + 고정` 배분량을 가용시간과 비교한다. 여유는 남겨 둘 수 있는 몫이므로 경고하지 않는다.
- **지난 날짜의 미완료:** 드로어의 ‘지난 미완료’를 중립 표기로 유지하고 끌어서 다른 날짜에 배정한다. 자동 이월은 하지 않는다.

### 5.3 편집창·우클릭·키보드

- 편집창의 `예정 날짜`와 `시작 시각`을 `날짜` + `시각 고정` 체크 + (고정일 때만) `시각`으로 바꾼다. 저장하면 상태 전이에 맞는 명령으로 나눠 보낸다. 제목·본문은 `Update`, 날짜·고정은 `AssignDate`/`Fix`/`Unfix`이다.
- 우클릭 메뉴에 `시각 고정…`/`고정 해제`, `앞으로`/`뒤로`, `미계획으로 옮기기`를 추가한다.
- 키보드: 블록이나 목록 행에 포커스한 상태에서 `Alt+↑/↓`로 순서를 바꾸고, Shift+F10이나 메뉴 키로 우클릭 메뉴를 연다. 드래그 없이 모든 전이를 할 수 있어야 한다(§11, §14 마지막 행).

## 9. 이번 계획의 범위 밖

- 부분 수행·잔여량 입력, 고정 일정의 조기 종료로 공간 해제(§12, D7의 후속)
- 재실행·절전 복귀·자정의 별도 정책. 지금은 anchor가 저장되므로 아무 동작도 하지 않는 것이 기본이다
- 알림, 분할 제안, 자동 이월, 생산성 점수
- 계획/수행 화면 분리 여부(§11). 같은 오늘 화면의 정보 밀도로 시작하고 실사용 관찰 후 판단한다

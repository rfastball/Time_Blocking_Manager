# BLOKKY

**할 일을 시간표에 배치하고, 끝낸 만큼 남은 일정을 정리하는 Windows용 오프라인 앱.**

시간표를 계속 고치는 부담을 줄이기 위해 만들었습니다. **할 일의 날짜·순서·배분할 시간**을 정하면 빈 시간에 순서대로 배치합니다. 회의처럼 시작 시각을 지켜야 하는 일은 따로 고정할 수 있습니다.

- **순서로 계획** — 일반 업무의 시작 시각을 일일이 정하지 않습니다.
- **블록으로 조작** — 끌어서 순서를 바꾸고, 아래쪽 경계를 늘려 작업에 배분한 시간을 조절합니다.
- **완료하면 재배치** — 오늘의 일반 업무를 완료하면, 남은 일이 고정 일정을 피해 현재 시각부터 다시 놓입니다.
- **작업대에서 다듬기** — 아직 날짜가 없는 일은 더미로 모아 두고, 도마에서 잘라 세부 작업으로 나눕니다.

로그인이나 네트워크 연결 없이 사용하며, 기록은 내 PC에 저장합니다. [최신 설치 파일 받기](https://github.com/rfastball/Time_Blocking_Manager/releases/latest)

## 작동 방식

### 블록의 길이는 작업에 배분한 시간

블록 하나는 작업 하나입니다. 60분 블록은 그 작업에 60분을 배분했다는 뜻이며, 실제로 일한 시간이나 진행률을 뜻하지 않습니다.

| 상태 | 사용자가 정하는 것 | 시간표에서의 동작 |
| --- | --- | --- |
| **미계획** | 할 일과 배분할 시간(나중에 정해도 됨) | 날짜를 정하기 전까지 작업대의 더미에 보관 |
| **유동계획** | 날짜·순서·배분할 시간 | 시작 시각을 고정하지 않고, 휴식과 고정 작업을 피해 배치 |
| **고정계획** | 날짜·시작 시각·배분할 시간 | 다른 작업이 움직여도 지정한 시각을 유지 |

유동 작업은 정해 둔 순서를 지키며, 한 블록을 여러 시간대로 자동 분할하지 않습니다. 예를 들어 60분 작업은 30분짜리 빈 시간 두 곳에 나눠 넣지 않습니다. 근무시간 안에 들어가지 못한 작업부터는 순서대로 근무 종료 뒤에 놓고, 점선과 **근무 외 시간**으로 표시합니다.

### 끝낸 일은 빼고, 남은 일은 지금부터

오늘의 유동 작업을 완료하거나 **재배치**를 누르면, 남은 유동 작업이 현재 시각부터 다시 놓입니다. 각 작업에 배분한 시간과 순서는 유지합니다. 시간이 흐르거나 앱을 다시 여는 것만으로는 재배치하지 않습니다.

고정 작업은 완료해도 지정한 시간대를 차지합니다. 다른 작업이 그 시간대를 쓰게 하려면 고정을 풀거나 고정 시각을 옮깁니다.

![유동 작업을 완료한 뒤 남은 블록을 다시 배치하는 모습](assets/readme/completion.gif)

*09:40에 첫 작업을 완료하면 다음 작업이 09:40부터 놓입니다. [정지 화면](assets/readme/completion.png)*

타이머를 켜고 끄거나 실제 수행시간을 입력할 필요는 없습니다.

### 직접 바꾸고 로컬에 남기기

**계획**에서는 날짜와 시간을 배치하고, **오늘**에서는 다음 할 일과 남은 작업을 확인하며 완료합니다. **미계획**은 블록의 모양(길이·쪼개기·묶음)을 정하는 작업대입니다. 어느 화면에서든 작업 제목을 누르면 제목과 메모를 편집할 수 있고, `Ctrl+K` **검색**으로 어디에 있는 작업이든 찾아갑니다.

작성 중인 초안, 휴지통, 로컬 백업을 두고 종료·복원·업데이트 과정에서도 기록을 보호합니다. 계획을 유지하는 데 드는 주의를 줄이고 실제 수행에 집중할 수 있도록 설계했습니다.

설계의 배경은 [유동형 업무 배분 재설계안](docs/BLOKKY_redesign_intent_and_ux.md), 현재 정책은 [제품 정의](PRODUCT.md)와 [구현 결정](docs/decisions.md)에 기록합니다.

## 직접 조작 데모

### 레일에 걸면 시각 고정, 떼면 다시 순서로

**고정 레일**은 시간 눈금 옆의 세로 막대입니다. 블록을 레일 쪽으로 밀면 걸쇠가 나타나고 시작 시각이 15분 단위로 고정됩니다. 레일을 따라 위아래로 옮기면 고정 시각이 바뀌고, 오른쪽 작업 영역으로 떼어 내면 유동 작업으로 돌아옵니다. 주변 유동 작업은 고정된 시간대를 피해 다시 놓입니다.

![블록을 레일에 걸어 11시에 고정하고, 10시로 옮긴 뒤 다시 유동 작업으로 바꾸는 모습](assets/readme/rail-latch.gif)

*11시에 고정 → 10시로 이동 → 고정 해제. 위아래로 옮길 때의 작은 좌우 흔들림으로는 고정되지 않도록 조작을 구분합니다. [정지 화면](assets/readme/rail-latch.png)*

### 경계에서 멈추고, 더 밀면 겹친 부분만 표시

고정 블록을 끌어 점심이나 근무 종료 경계를 넘기려 하면 경계에서 한 번 멈춥니다. 더 밀면 이동을 허용하고, 근무·휴식 설정상 일할 수 없는 구간과 겹친 부분만 빗금으로 표시합니다.

![11시부터 12시까지의 고정 작업을 점심 경계로 밀어 넣으면 경계에서 저항하고, 더 밀면 점심에 걸친 15분만 빗금으로 표시하는 모습](assets/readme/boundary-response.gif)

*11:00–12:00 작업을 11:15–12:15로 옮기면 점심과 겹친 15분에 빗금이 생깁니다. [정지 화면](assets/readme/boundary-response.png)*

## 사용법

### 1. 생각나는 일을 담기

**미계획** 입력란에 제목을 쓰고 `Enter`를 누르면 **투입구** 맨 위에 담깁니다. 담기만 한 작업은 길이를 정하기 전까지 테두리만 있는 **길이 미정** 카드로 남습니다. 카드 아래쪽 경계를 끌거나 `↑`/`↓`로 15분 단위 길이를 정하며, 길이 미정인 채로 날짜에 놓으면 30분으로 정해집니다.

다른 앱에서 일하는 중에는 `Ctrl+Shift+Space`로 **빠른 캡처** 창을 엽니다. `Enter`로 저장하고, `Shift+Enter`로 줄을 바꾸며, `Esc`로 초안을 보존한 채 숨깁니다. 단축키는 설정에서 변경할 수 있습니다.

### 2. 작업대에서 모양 잡기

**미계획** 화면은 지난 미완료, 투입구, 사용자가 만든 **더미**를 레일에 매달린 카드로 보여 주고, 오른쪽에 오늘과 다음 근무일 4일의 **날짜 열**을 둡니다.

| 놓는 곳 | 결과 |
| --- | --- |
| 더미 안 | 그 위치에 끼움 |
| 더미 사이·빈 곳 | 새 더미 |
| 날짜 열 | 그날 순서 끝에 배치(착지 위치와 근무 외로 넘치는 부분을 미리 표시) |

더미 손잡이는 카드 수와 합계 시간을 보여 줍니다. 손잡이를 끌면 더미를 옮기거나 다른 더미에 합치거나 날짜 열에 통째로 싣고, 누르면 더미의 카드를 모두 선택합니다. 선택한 카드는 아래 막대에서 한꺼번에 날짜에 싣기·완료·삭제합니다.

카드를 누르면 두 배 크기의 **도마**가 열립니다. 도마는 제목·메모 편집기를 겸하며, 큰 작업을 세부 작업으로 자르는 곳입니다.

- 칼선으로 15분 단위로 자르고, 조각 사이 이음매를 끌어 시간을 주고받으며, 이음매를 두 번 눌러 다시 잇습니다.
- 조각 이름을 입력해 추가하거나, 메모의 체크리스트로 조각을 한 번에 만듭니다.
- 닫으면 각 조각이 원래 자리부터 연달아 놓이는 독립 작업이 됩니다. **취소**는 이번 편집을 버립니다.

계획·오늘의 블록 메뉴와 편집기의 **나누기**도 같은 도마를 엽니다. 날짜 블록을 나누면 조각이 그날 순서에 연달아 놓이고, 고정 블록이면 원래 시작 시각부터 이어서 고정됩니다.

### 3. 하루에 배분하기

**계획**의 시간표에 미계획 작업을 끌어 놓습니다. 미계획 칸은 투입구부터 더미를 왼쪽에서 오른쪽, 각 더미 안에서 위에서 아래 순서로 보여 줍니다. 작업 영역에 놓으면 그날의 유동 작업이 됩니다. 시작 시각을 정해야 한다면 시간 눈금 옆 **고정 레일**에 놓습니다.

| 보기 | 용도 |
| --- | --- |
| **일** | 하루를 넓게 펼쳐 블록을 만들고 배치 |
| **주** | 여러 날짜의 시간표를 함께 보고 작업 이동 |
| **2주** | 날짜별 작업 제목을 보고 선택 날짜의 시간표 확인 |
| **월** | 날짜별 작업량을 보고 선택 날짜의 시간표 확인 |

주 보기의 날짜 제목이나 2주·월 보기의 선택 날짜 제목을 누르면 **일** 보기로 이동합니다. 일·주 시간표의 빈 곳을 클릭하면 그날 순서 끝에 새 유동 블록을 만듭니다. 시간 범위를 드래그하면 선택한 시작 시각과 길이의 고정 블록을 만듭니다.

블록 하단 손잡이로 길이를 바꿉니다. 우클릭 메뉴에서는 완료·순서 변경·고정/해제·나누기·미계획 이동을 선택할 수 있습니다.

- **나누기** — 도마를 열어 블록을 여러 작업으로 자릅니다.
- **하루 비우기** — 그날의 미완료 작업을 삭제하지 않고 모두 미계획으로 돌립니다. 완료한 블록은 그날의 기록으로 남습니다.

### 4. 오늘 할 일에 집중하기

**오늘**에서 시간표, **다음** 할 일, 남은 작업 목록, 미계획을 확인합니다. 제목을 누르면 내용을 편집하고, 완료 체크를 누르면 작업을 완료합니다. 시간표의 여러 블록을 `Shift` 또는 `Ctrl`+클릭해 한 번에 완료할 수도 있습니다.

완료한 작업 없이 현재 시각부터 다시 배치하려면 **재배치**를 누릅니다. 시간표에 새 블록을 만들거나 하루 계획을 편집하려면 **계획 → 일**로 이동합니다.

모든 완료에는 날짜가 있습니다. 미계획 작업을 완료하면 오늘의 완료로 기록하며 시간표를 다시 배치하지 않습니다. 날짜가 정해진 작업은 그 날짜에 완료로 남습니다.

지난 날짜의 미완료 작업은 작업대의 **지난 미완료**에 모이며, 직접 다른 날짜나 더미로 옮깁니다. 자동으로 다음 날에 이월하지 않습니다.

### 5. 작업 찾기

메뉴의 **검색** 또는 `Ctrl+K`로 검색창을 엽니다. 작업대·모든 날짜·완료·휴지통의 제목과 메모를 부분 일치로 찾고, 결과마다 지금 있는 위치를 보여 줍니다. `↑`/`↓`로 고르고 `Enter`를 누르면 그 작업이 있는 화면으로 이동해 강조합니다. 한글을 조합하는 중에도 결과가 갱신됩니다.

### 6. 근무 리듬과 반복 업무 맞추기

- **설정 → 근무시간**에서 요일별 근무·휴식과 주간 목표를 정합니다. 기본 목표는 40시간·5일이며, 실제 근태가 아닌 예정 근무량입니다.
- 시간표의 근무 외 시간이나 휴식을 클릭하면 그 날짜만의 출퇴근·점심·휴가 예외를 설정할 수 있습니다. 고정 작업과 충돌하는 변경은 영향 작업을 확인하고 동의한 뒤 저장합니다.
- **정기 업무**에 요일·시작 시각·작업 시간을 등록하면 오늘을 포함한 이후 날짜 중 화면에 표시된 날짜에 작업을 만듭니다. 근무·휴식 설정이나 다른 고정 작업과 겹치면 같은 날짜의 유동 작업으로 만듭니다. 정기 업무를 수정·삭제해도 이미 생성한 작업은 바뀌지 않습니다.
- **테마**는 기본·종이 플래너·톤 레이어·사무 장부의 2×2 미리보기에서 선택합니다.

## 기록과 복구

업무 기록은 로컬 SQLite에 저장합니다. 기본 위치는 `%LOCALAPPDATA%\com.blokky.desktop` 폴더의 `blokky.sqlite`이며, 실제 경로는 앱 설정에서 확인할 수 있습니다.

| 보호 장치 | 동작 |
| --- | --- |
| **초안** | 입력 중인 내용을 별도로 보존하고, 복원된 편집은 ‘이어서 편집’으로 열기 |
| **휴지통** | 삭제한 작업을 30일간 보관하고 원래 날짜·순서·완료 상태로 복원. 미계획 작업대 맨 아래에 접혀 있음 |
| **자동 백업** | 시간별 24개, 날짜별 30개를 보존 |
| **지금 백업** | 앱 데이터 폴더의 `backups`에 수동 백업 생성 |
| **복원 전 보호** | 미저장 입력을 먼저 정리하고, 현재 기록 교체 확인 및 안전 백업 후 복원 |

휴지통에서 복원할 고정 작업의 시각이 다른 고정 작업이나 근무·휴식 설정과 겹치면, 같은 날짜의 유동 작업으로 복원합니다. 개별 영구 삭제와 휴지통 비우기도 제공합니다.

이전 버전에서 날짜 없이 완료한 기록은 작업대 아래 접힌 **날짜 없는 완료** 목록에 남습니다. 항목마다 투입구로 되돌리거나 삭제할 수 있고, **보관 목록 비우기**로 한꺼번에 휴지통으로 옮깁니다.

백업은 **설정 → 백업·복원**의 앱 내부 목록에서 검사하고 복원합니다. 손상된 백업은 오류 이유와 함께 비활성화하며, 현재 DB가 열리지 않아도 보관된 백업으로 복구를 시도할 수 있습니다. 수동 백업과 복원 전 안전 백업은 자동 정리 대상에서 제외합니다.

SQLite 백업에는 작업·더미·휴지통·근무 설정·정기 업무·정기 업무의 날짜별 생성 이력이 들어갑니다. 테마·빠른 캡처 단축키·자동실행·창 닫기 옵션은 별도 기기 설정이므로 백업 복원으로 바뀌지 않습니다.

파일 탐색기로 임의 백업을 가져오거나 외부 경로로 내보내는 기능은 없습니다. 백업도 앱 데이터와 같은 디스크에 저장되므로 디스크 고장에 대비하는 별도 사본을 대신하지는 못합니다.

## 기술 스택

| 계층 | 기술 | 맡은 역할 |
| --- | --- | --- |
| 화면 | **React 19 · TypeScript · Vite 7** | 오늘·계획·미계획 작업대·도마·검색·설정과 브라우저 미리보기 |
| 직접 조작 | **@dnd-kit/core · motion** | 드래그 감지, 배치 전환과 완료 동작 |
| 디자인 | **CSS 역할 토큰 · 로컬 글꼴** | 네 가지 테마와 공통 색·간격·크기 규칙 |
| 데스크톱 | **Tauri 2 · Rust · WebView2** | Windows 창, 전역 단축키, 트레이, 자동실행 |
| 저장 | **SQLite · rusqlite** | 트랜잭션, 초안, 이관, 백업·복구 |
| 검증 | **Node test runner · Rust tests · 헤드리스 Edge** | 순수 로직, 실제 파일 저장소, 명시적 UI 시나리오 |

React 화면의 변경 요청을 Tauri IPC로 전달하면 Rust가 검증해 SQLite에 기록합니다. SQLite는 WAL·FULL synchronous로 동작합니다. 항목 버전(revision)을 검사해 오래된 편집이 최신 기록을 덮어쓰지 못하게 하고, 같은 요청의 중복 처리를 막습니다. 이미 저장된 요청은 처리 기록을 먼저 확인해 완료 처리하며, 입력을 수정해도 결과가 확정되지 않은 이전 요청은 별도로 보존합니다. 처리 기록은 30일 보관하며, 기록이 없는 오래된 요청은 입력을 유지하고 저장 여부를 확인하도록 합니다. 확인할 수 없는 요청을 새 저장으로 바꾸려면 중복 가능성을 확인해야 합니다. 백업 복원 전의 요청도 복원 후 기록에 적용하지 않습니다. 로그에는 제목·메모를 남기지 않습니다.

## 개발 내용

- **로컬 업무 흐름** — 빠른 캡처부터 미계획·정기 업무·근무시간·날짜 예외까지 연결했습니다. [제품 정의](PRODUCT.md)
- **유동형 배분** — 날짜·순서 중심 계획, 고정 일정 우회, 완료·수동 재배치와 근무 외 넘침 표시를 구현했습니다. [재설계안](docs/BLOKKY_redesign_intent_and_ux.md) · [구현 계획](docs/BLOKKY_redesign_implementation_plan.md)
- **React 화면 전환** — 공통 블록 공간과 편집기를 만들고, 오늘 대시보드와 계획의 일·주·2주·월 보기를 구성했습니다. [React 도입 계획](docs/BLOKKY_react_migration_plan.md)
- **미계획 작업대와 검색** — 더미·길이 미정 카드·날짜 열로 미계획을 정리하고, 도마로 작업을 쪼개며, 모든 작업을 한 검색창에서 찾도록 했습니다. [제품 정의](PRODUCT.md) · [구현 결정](docs/decisions.md)
- **직접 조작 개선** — 블록이 포인터를 따라오도록 하고, 레일 맞물림·길이 조절과 이웃 블록의 이동을 다듬었습니다. [구현 결정](docs/decisions.md)
- **입력과 기록 보호** — 한글 조합 중 명령 방지, 초안 복원, 종료 전 저장, 휴지통, DB 이관·백업 복구를 구현했습니다. [검증 기록](docs/validation.md)
- **화면 품질** — 테마 토큰, 키보드 조작과 포커스 복귀, 좁은 창 배치, 날짜·작업의 글자 대비를 개선했습니다. [디자인 기준](DESIGN.md) · [검증 기록](docs/validation.md)

현재 저장소는 **스키마 7**입니다. v1–v3의 배치 작업은 고정 작업으로 읽고, v4에는 휴지통 정보를, v5까지의 기록에는 더미·길이 미정 정보를 추가해 이관합니다. 이전 미계획 목록은 순서를 유지한 채 투입구가 됩니다. v6의 더미 순서는 그대로 유지하며, 처리 기록에 정리용 시각을 추가합니다. 이관 직전에 안전 백업을 만들며, 새 스키마를 지원하지 않는 구버전 앱의 접근은 차단합니다.

## 개발 환경

설치 파일은 [Releases](https://github.com/rfastball/Time_Blocking_Manager/releases)에서 받을 수 있습니다. 소스에서 앱을 실행하거나 설치 파일을 만들려면 Windows에 **Node.js 22.12+**, Rust, MSVC C++ 빌드 도구, WebView2가 필요합니다.

### 데스크톱 앱 실행

저장소 루트의 PowerShell에서 실행합니다.

```powershell
npm ci
./scripts/run.ps1 dev
```

스크립트는 `.tools/cargo`의 로컬 Rust가 있으면 우선 사용하고, 없으면 시스템 환경을 사용합니다. 개발 서버는 1420부터 가용 포트를 선택해 Tauri에 전달합니다. 이전 개발 앱이 실행 중이면 트레이에서 종료한 뒤 다시 시작합니다.

### 화면만 미리 보기

의존성을 아직 설치하지 않았다면 먼저 `npm ci`를 실행합니다.

```powershell
npm run dev
```

터미널에 출력된 로컬 주소를 열면 예시 화면을 볼 수 있습니다. 브라우저에서 바꾼 내용은 **저장되지 않습니다**. 실제 저장·백업은 데스크톱 앱에서 확인합니다.

### 검증과 패키징

```powershell
./scripts/run.ps1 test -NoPause   # 프런트 로직 + Rust 저장소 테스트
npm run build                   # TypeScript 검사 + 프런트 배포 빌드
./scripts/run.ps1 package        # Windows NSIS 설치 파일 생성
```

UI 확인은 개발 서버 실행 후 별도로 수행합니다. `--base`에는 실제 출력된 주소를 지정합니다.

```powershell
node scripts/ui-check.mjs --base http://127.0.0.1:1420
```

이 검사는 헤드리스 Edge의 마우스·키보드 입력을 사용하며 기본 `npm test`에 포함되지 않습니다. 네이티브 디버그 앱은 `BLOKKY_TEST_DATA_DIR`로 시험 데이터 위치를 분리할 수 있습니다. 검증 계층과 비용 기준은 [테스트 정책](docs/test-policy.md)을 참고하세요.

생성된 설치 파일은 `src-tauri/target/release/bundle/nsis/`에 있습니다. WebView2 오프라인 설치기를 포함하며 코드 서명은 적용하지 않았습니다. WebView2가 이미 설치된 PC에서는 `src-tauri/target/release/blokky.exe`를 직접 실행할 수도 있습니다. 최신 변경을 포함하려면 소스를 갱신한 뒤 패키징 명령을 다시 실행하세요.

## 현재 범위와 검증 상태

버전은 **0.2.0**, 대상은 **Windows**입니다. 추천·알림·자동 이월·클라우드 동기화·협업·자정을 넘는 블록·복잡한 반복 규칙은 지원하지 않습니다. 작업에 배분한 시간을 실제 근태나 수행시간 통계로 기록하지 않습니다.

[검증 기록](docs/validation.md)에서 변경 날짜별로 자동 테스트, 브라우저 조작, 실제 DB 저장, Windows 앱과 설치 파일의 확인 결과를 볼 수 있습니다. 0.2.0은 프런트 테스트 60개, Rust 저장소 테스트 22개와 Windows 설치 파일 패키징을 확인했습니다. 모든 Windows 환경, 실제 마우스·터치·한글 입력, 스크린리더, 최신 설치본 전체를 검증한 상태는 아닙니다.

처음 수정한다면 [제품 정의](PRODUCT.md)로 동작 범위를 확인하고, [구현 결정](docs/decisions.md)과 [테스트 정책](docs/test-policy.md)을 함께 읽어 주세요.

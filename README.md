# BLOKKY

할 일 담기 → 블록 크기 정하기 → 시간표에 배치하기를 위한 Windows 로컬 업무 앱.
Tauri 2 + Rust + SQLite, TypeScript + Vite로 구현한다. 런타임에 로그인·네트워크가 필요 없다.

## 실행

설치 파일: `src-tauri/target/release/bundle/nsis/BLOKKY_0.1.0_x64-setup.exe` (2026-10-09 품질 개선 1단계 반영, 216.09 MiB).
WebView2 오프라인 설치기를 포함하며 코드 서명되지 않았다. 이미 WebView2가 설치돼 있으면 `src-tauri/target/release/blokky.exe`로 실행할 수 있다. 설치·실행과 전체 UI 검증 여부는 [검증 기록](docs/validation.md)에 구분해 기록한다.

1. **미계획**에 생각나는 일을 제목으로 바로 담고, 소요시간을 정한다. 기본 30분, 15분 눈금이다.
2. **계획**의 기본 주간 시간표에 할 일을 끌어 놓는다. 우측 미계획 드로어는 열고 닫을 수 있다. **2주**는 작업 제목, **월**은 날짜별 작업량을 보여주며 선택 날짜 시간표를 함께 제공한다.
3. 주간·날짜 시간표의 빈 곳을 클릭하거나 드래그해 새 블록을 만들고 인라인 제목을 입력한다. 기존 블록은 길이를 유지하며 다른 날짜로 옮길 수 있다.
4. 블록 하단 손잡이를 끌거나, 손잡이에 포커스하고 위/아래 화살표로 길이를 바꾼다. 우클릭하면 편집·완료·나누기·미계획 이동을 선택한다. 블록 안 분할 경계를 끌어 분할 위치를 정할 수 있다. 나눈 뒤 블록은 미계획에 남고 총 시간과 메모는 보존된다.
5. 편집창은 메모를 먼저 보여 주고 시간·날짜·블록 크기는 접힌 영역에서 수정한다. **저장**에 성공하면 닫힌다. 체크리스트가 상위 항목을 자동 완료하지 않는다.
6. 지난 미완료는 계획 화면에서 기존 항목을 이동한다. 복원된 편집 초안은 **이어서 편집**으로 열며 오류와 재시도 안내는 화면에 남는다.

**시간 조정** 또는 금지시간을 클릭해 해당 날짜의 출퇴근, 점심 예외, 휴가·조퇴를 설정한다. 반복 요일 일정은 설정에서 변경하며 날짜 변경은 해당 날짜에만 적용된다. 겹치는 작업은 사용자가 명시적으로 선택해야 미계획으로 옮긴다.

주간 목표는 기본 40시간·5일이다. 출퇴근 합계에서 금지시간을 뺀 예정 근무시간이며 실제 근태 측정값은 아니다.

`Ctrl+Shift+Space`는 520×132 제목표시줄 없는 빠른 캡처창을 연다. **설정 → 빠른 캡처**에서 단축키를 변경한다. Enter로 저장, Shift+Enter로 줄바꿈, Esc로 초안을 보존한 채 숨긴다. 창 닫기는 트레이 숨김이며 트레이 메뉴에서 종료한다.
미저장 입력이나 실패 요청이 있으면 종료·복원을 막고 입력을 유지한다.
자동실행은 설정에서 직접 켠다.

## 기록과 백업

- 활성 DB: `%LOCALAPPDATA%/com.blokky.desktop/blokky.sqlite` (실제 위치는 앱 설정에서 확인).
- SQLite WAL + FULL synchronous. 항목별 쓰기, revision 검사, 중복 요청 방지.
- 초안은 SQLite에 별도로 보관하며 저장한 항목과 구분한다.
- 설정의 백업·복원 영역에서 시간별·날짜별 자동 백업(각 24개·30개 보존)과 직접 만든 백업을 함께 목록으로 관리한다. **지금 백업**은 앱 데이터 폴더 안의 `backups`에 새 UUID로 저장한다.
- 목록에는 백업 종류·생성 시각·작업 수가 표시된다. 유효한 항목을 선택하면 전체·배치·완료 건수를 확인하고, 현재 기록 교체를 같은 화면에서 확인한 뒤 복원한다. 손상되었거나 읽을 수 없는 항목은 오류 이유와 함께 비활성화한다.
- 파일 탐색기에서 임의 백업을 고르는 가져오기와 외부 경로로 내보내기는 제공하지 않는다. 백업은 앱 내부 목록에서 관리한다.
- 직접 만든 UUID 백업과 복원 전 안전 백업(`before-restore-<UUID>.sqlite`)은 자동 보존 정리 대상이 아니다.
- 복원 중 미저장 편집·설정 초안은 복원을 막고 유지한다. 저장소/백업 오류에서 현재 기록을 성공 상태로 표시하지 않는다.
- 현재 DB를 열지 못하면 오류 화면의 백업·복원에서 보관된 백업을 검사하고 복구할 수 있다. 손상 기록과 관련 파일은 복구 자료로 보존한 뒤 선택 백업으로 교체하며, 실패하면 성공으로 표시하지 않는다.
- SQLite 백업은 작업과 근무 설정을 포함한다. 화면 테마·빠른 캡처 단축키·Windows 자동실행 설정은 별도 보관되며 이 백업의 복원 대상이 아니다.
- 로그 `blokky.log`에는 경로·버전·오류 코드·백업 결과만 기록한다. 제목·본문을 기록하지 않는다.

## 개발

Node.js 22.12+와 [Tauri Windows 필수 도구](https://v2.tauri.app/start/prerequisites/)(MSVC C++ 빌드 도구·Rust·WebView2)가 필요하다.

```powershell
npm ci
./scripts/run.ps1 dev
./scripts/run.ps1 test
./scripts/run.ps1 package
```

이 작업에서 설치한 Rust는 `.tools`에 있으며 스크립트가 있으면 자동 사용한다. 시스템 PATH는 변경하지 않는다.
`run.ps1`은 실패 시 오류를 표시하고 Enter를 기다린다. 자동 실행에서는 `-NoPause`를 사용한다. 개발 앱이 이미 실행 중이면 작성 내용을 저장한 뒤 트레이 아이콘의 **종료**로 끝내고 다시 실행한다. 창의 X는 앱을 숨기므로 실행 파일 잠금이 풀리지 않는다.
`npm run dev`는 **저장하지 않는 예시 데이터 미리보기**다. 실제 저장 검증은 데스크톱 앱에서 수행한다.
개발 서버는 1420부터 사용 가능한 포트를 자동 선택한다. 터미널에 출력된 주소로 웹 미리보기를 연다. `npm run desktop` 또는 `./scripts/run.ps1 dev`는 선택된 주소를 Tauri에 전달한다. 직접 `npm run tauri -- dev`를 실행하면 고정 포트를 사용하며, 1420이 사용 중이면 실패한다.
디버그 바이너리만 `BLOKKY_TEST_DATA_DIR` 환경변수로 테스트 데이터 위치를 분리할 수 있다.

## 범위와 검증

자동 배치·알림·동기화·자정 넘김·일반 반복 Task는 지원하지 않는다.
저장소는 스키마 2로 전환된다. 기존 스키마 1 기록·백업을 읽을 수 있으며, 날짜 예외를 모르는 구버전 앱으로 스키마 2를 열 수 없다.
결정 근거는 [구현 결정](docs/decisions.md), 검증 상태는 [검증 기록](docs/validation.md)을 참고한다.
단독형 캘린더40개 품질 목표의 [개선 계획](docs/calendar-quality-action-plan-2026-10-09.md)에 따라 복구·조합 입력·날짜 표시부터 개선한다. 원문 목표 전체의 검증 완료를 뜻하지 않는다.
현재 버전은 첫 구현이며, 확인하지 않은 Windows 시나리오는 검증 기록에 따로 명시한다.
